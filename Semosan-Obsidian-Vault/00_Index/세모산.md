# 세모산

## 2026-10-14 최신 확인 — 새 자소서 작성 시 우선 적용

출처: SK브로드밴드 자소서 작성 대화의 사용자 설명·정정. 개인 진술이며 독립 인증 아님. 아래 내용과 기존 본문이 다르면 아래 최신 범위를 적용한다.

- 등산 앱 10인 팀 PM. 팀원 대부분 등산 문화를 낯설어했다. 개발자는 기존 이용자가 많은 4050으로 주타깃 변경을 제안했고 본인은 2030 수요에 주목했다.
- 자료만으로 실제 수요를 충분히 알기 어렵고 직접 경험으로 가정을 검증하고자 팀원 9명과 관악산에 올랐다. 약 200명의 현장 인터뷰로 2030 수요·산행 기록·완등 성취·하산 후 맛집/막걸리까지의 코스를 확인했다. 최신 자소서는 200명을 2030으로 쓰지만 과거 기록은 전체 등산객으로도 표기한다. 전원 연령을 독립 확인한 것은 아니다.
- 본인도 운동·체력·다이어트 중심 가정에서 기록·성취·하산 후 활동의 중요성을 받아들였다. 현장 확인을 바탕으로 2030 타깃에 팀이 합의했다. 내 의견으로 상대를 이긴 이야기보다 본인 변화·의견 수용을 중심으로 쓴다.
- 개발자의 가벼운 추천 제안을 받아 온보딩 6문항→3문항으로 줄이고 30초 이내 산 추천을 목표로 구성했다. 코스까지 정확히 추천하는 방식에서 산 정도를 가볍게 추천하도록 바꿨다. 30초는 구성 목표이며 실측값 미확인.
- 하산 후 맛집 자동 추천 제안에는 BM 확장 가능성을 검토하고 산행 난이도 평가 화면에 추천을 추가할 수 있는 구조의 디자인을 요청했다. 자동 추천 구현 완료·매출로 확대하지 않는다.
- 산별 시설 정보가 통일되지 않아 백엔드 수집·디자인 표시가 어려웠다. 본인은 데이터를 확인해 화장실/편의점까지 필수였던 정책을 필요한 항목 중심으로 수정하고 누락 시설 정보는 AI로 공식 산 자료를 수집·추출하는 구조를 제안했다. 정보 누락과 시설 부재를 구분한다. 제안의 구현·합의 결과는 미확인.
- 최신 사용자는 방향이 불분명한 20개 기능→핵심 4개를 확인했다. 과거 10개 기록과 단계 차이는 미확정이므로 옛 10개를 새 자소서에 자동 재사용하지 않는다.
- 팀은 밋업 프로젝트 최우수상, 앱 출시, 현재 약 70명 회원 사용을 설명했다. 기준일은 이번 준비 시점으로 활성/누적 가입 정의는 미확인. 사용자 추정 개인 기획·조율 기여도 약 70%, 팀 전체 코드 개발의 70%로 확대하지 않는다.

재사용 에피소드: **SM-Q3 공동 산행으로 서로 다른 관점을 받아들이고 공동 방향을 정한 경험**. 타깃 차이→현장 검증→본인 인식 변화·팀 합의→추천 축소·맛집 제안 반영→20개를 4개로 집중·팀 수상. **SM-DATA 시설 데이터와 디자인 표시 기준을 조정한 사례**는 별도 보조 에피소드.

## 외부 피드백 기반 방향성 검증

세모산은 등산 중 사진을 찍고 남기고 싶어 하는 사용자 니즈를 핵심 니치 포인트로 보고, 사진 기록과 아카이빙 경험을 메인 기능 방향으로 잡았다. 실제 우디디자인랩 대표 우디님께서 서비스를 보고 등산객들이 사진을 찍고 남기고 싶어 하는 지점을 잘 포착했으며, 이를 메인 기능으로 잡은 점이 사업성 측면에서도 가능성이 있다고 피드백했다.

이 피드백은 세모산의 방향성이 단순 등산 정보 제공이 아니라, 등산객의 기록 욕구와 성취감을 중심으로 차별화될 수 있다는 외부 검증 근거로 활용한다.

## 추가 자소서 활동 기록 — SM-04

출처: [[삼성 자소서 원문]] 1번 지원동기.

- 문제: 10개 기능이 모두 핵심으로 논의돼 사용 흐름이 불분명했다.
- 수행: 2030 수도권 취미 등산객의 탐색→준비→등산→하산 후 여정을 구체화했다. 현장 관찰과 조사를 바탕으로 산 탐색·실시간 정보 확인·트래킹·등산 인증 및 공유의 4개 기능에 집중했다.
- 결과 기록: 삼성 초안은 전시 체험자 93.2%가 다음 등산에서 기록·공유 기능을 사용할 의향을 보였다고 기록한다.
- 범위·확인 사항: SM-02와 같은 기능 축소 사건의 고객 여정 관점이다. 93.2%는 이용 의향이며 실제 재사용·전환·유지율이 아니다. 전시 응답의 분모·문항 확인 전 24명 UT 결과로 합치지 않는다.
