# 관계 타입 규칙

## 관계 타입

- `defines`: 문제나 목표를 정의한다.
- `validates`: 리서치, UT, QA, 피드백으로 검증한다.
- `implements`: 기획을 코드, 화면, 로우코드, API로 구현한다.
- `supports`: 데이터 모델, 디자인 시스템, 인프라, 문서가 기능을 뒷받침한다.
- `evidenced_by`: 산출물, 회의록, GitHub, Figma, Notion, PDF 등으로 근거가 있다.
- `translates_to`: JD나 포트폴리오 문장으로 변환된다.
- `strong_for`: 특정 직무/JD에서 강하게 활용된다.
- `weak_for`: 특정 직무/JD에서 보조 근거로만 활용한다.
- `needs_context`: 추가 정보가 있어야 더 정확하게 말할 수 있다.

## 예시

- [[파밍 패밀리 캡스톤]] `implements` [[AI 활용]]
- [[큐시즘 리트머스]] `strong_for` [[AX]]
- [[세모산]] `validates` [[사용자 리서치]]
- [[구름톤유니브 포인커리어]] `evidenced_by` GitHub 커밋과 Swagger
- [[리스크 매니저]] `translates_to` [[AI 활용]]과 [[UX UI]]

## 작성 원칙

- `본인이 했다`와 `팀이 했다`를 분리한다.
- 기업 협업, 실제 사용자, 실제 사용 여부는 강한 근거로 본다.
- 수업 프로젝트도 실제 회사 협업, 구현, 시연, 피드백이 있으면 포트폴리오에 넣을 수 있다.
- 단순 참여보다 문제를 어떻게 판단하고 바꿨는지를 우선 기록한다.
