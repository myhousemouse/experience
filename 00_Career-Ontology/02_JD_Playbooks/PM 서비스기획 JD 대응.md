# PM 서비스기획 JD 대응

## PM/서비스기획 JD에서 자주 나오는 요구

- 문제 정의
- 사용자 리서치/UT
- 요구사항 정의
- 기능 우선순위
- 화면 흐름/정책 설계
- 개발/디자인 협업
- 데이터와 근거 기반 의사결정

## 우선 조합

1. [[세모산]]
   - UT, 기능명세, 최종 GUI, 디자인 시스템, API/ERD까지 연결된 제품 경험

2. [[큐시즘 리트머스]]
   - 실제 기업 과제에서 MVP를 만들고 실제 사용까지 연결한 경험

3. [[인플레이스]]
   - 파트별 회의록, PRD, 최종 GUI 우선순위 기반 협업 경험

4. [[CODE 데이터베이스 시스템 프로젝트]]
   - 실제 회사 업무를 DB 설계와 와이어프레임으로 구조화한 경험

## 포트폴리오 흐름

1. 사용자/기업/팀 문제를 발견했다.
2. 회의록, UT, GUI, 데이터 구조를 통해 문제를 구체화했다.
3. 개발 가능한 단위로 명세화했다.
4. 충돌이 있을 때 최종 GUI, 최신 회의록, 기업 피드백 등 우선 기준을 세웠다.

## 대표 문장

> 저는 기획을 문서로 끝내기보다, 화면과 개발 산출물로 이어질 수 있게 정리하는 편입니다. 세모산에서는 UT와 최종 GUI, API/ERD를 함께 보며 기능을 정리했고, 리트머스에서는 기업 피드백을 기준으로 MVP 범위와 우선순위를 조정했습니다.
