# 개발협업 백엔드 JD 대응

## 기술 직무/JD에서 자주 나오는 요구

- API 구현
- DB/ERD 이해
- GitHub 기반 협업
- Swagger/API 문서
- 배포/인프라 이해
- 문제 해결 과정 설명
- 기획 의도를 이해한 구현

## 우선 조합

1. [[구름톤유니브 포인커리어]]
   - Spring 백엔드, ERD, API, 더미데이터, Docker/env 세팅 보조

2. [[단풍톤 꿈마중 버스]]
   - 백엔드 API, 방문순서/ETA 산출 로직, 균형 클러스터링

3. [[파밍 패밀리 캡스톤]]
   - Python/FastAPI 기반 챗봇 시스템 구현

4. [[AWS 인프라 학습]]
   - EC2, VPC, RDS, CloudWatch, 서버리스 API 등 인프라 이해 보조 근거

## 주의할 점

- 배포를 주도하지 않은 경우 “세팅과 보조”라고 표현한다.
- 단풍톤은 프론트 연동 미완료를 숨기지 않고, 백엔드 API/산출 로직은 동작했다고 말한다.
- 포인커리어는 직접 구현 API와 팀 구현 범위를 계속 분리한다.

## 대표 문장

> 저는 기획 배경을 이해한 상태에서 백엔드 구현까지 경험했습니다. 포인커리어에서는 ERD와 API, 더미데이터를 다뤘고, 단풍톤에서는 방문 순서와 ETA 산출 로직을 구현했습니다. 캡스톤에서는 챗봇이 서비스 핵심이라고 판단해 FastAPI 기반 챗봇 구현까지 직접 맡았습니다.
