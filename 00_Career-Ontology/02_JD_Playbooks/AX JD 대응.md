# AX JD 대응

## AX JD에서 자주 나오는 요구

- AI/자동화 기술을 활용한 업무 개선
- 현업 부서의 문제 정의와 요구사항 정리
- 내부툴/대시보드/운영 프로세스 개선
- 데이터 기반 의사결정
- PoC, MVP, 프로토타입, 빠른 검증
- 개발자/디자이너/현업 간 커뮤니케이션

## 우선 조합

1. [[큐시즘 리트머스]]
   - 실제 기업 과제와 AX 교육형 인턴으로 이어진 경험
   - 내부 대시보드 UX 개선, PM/법무 기능 제안, 실제 업무 투입

2. [[텃밭닥터 캡스톤]]
   - 기획자가 챗봇 핵심 기능을 직접 구현한 경험
   - Python/FastAPI, 챗봇 구조, 사용자 2차 질문 대응

3. [[리스크 매니저]]
   - AI 분석 결과의 신뢰성을 UX와 로직으로 보완한 경험
   - Cold Start, 낙관/비관 페르소나, 끊어서 생각하기

4. [[인크루트 데이터라벨링팀 현장실습 인턴]]
   - AI 데이터 품질과 라벨링 기준 정립 경험
   - 모호한 기준을 클라이언트와 맞추기 위한 대안 제시

## 포트폴리오 흐름

1. 실제 기업/현업 문제를 이해했다.
2. AI나 자동화를 무작정 붙이지 않고, 업무 흐름을 먼저 봤다.
3. 사용자/현업이 신뢰할 수 있도록 기준, 근거, UX를 만들었다.
4. 구현 또는 프로토타입까지 연결했다.

## 대표 문장

> 저는 AI를 단순히 기능으로 붙이는 것보다, 사용자가 결과를 신뢰하고 실제 업무에서 쓸 수 있는 흐름을 만드는 데 관심이 있습니다. 리트머스 인턴에서는 내부 대시보드의 UX와 부서별 기능 요구를 정리했고, 캡스톤에서는 챗봇 핵심 기능을 직접 구현했습니다. 리스크 매니저에서는 AI 분석 결과의 신뢰성을 높이기 위해 낙관/비관 페르소나와 단계별 사고 흐름을 설계했습니다.
