# 2026-11-03 소프티어 부트캠프 지원서 제출 업데이트

기준일: 2026-11-03. 사용자가 소프티어 부트캠프 지원서의 학내외활동 3개와 직장경력 3개를 최종 제출했다고 확인했다. 아래 내용은 이번 지원서에서 사용한 역할·수치·성과의 최신 기준이다. 향후 자소서 작성 시 기존 기록과 충돌하면 아래 사용자 확인 내용을 우선하되, 제출 문구와 독립 인증 자료는 구분한다.

## 학내외활동 최신 제출 사실

### 세모산

- 10인 팀 PM으로 2030을 위한 기록형 등산 앱을 기획했다.
- 2030과 4050 중 핵심 이용자를 정하기 위해 SNS 게시물과 산 인접역 이용량을 확인했다. `#관악산` 게시물 31.7만 건, 산 인접역 이용객 전년 대비 평균 11.5% 증가를 제출서에 사용했다.
- 팀을 5명씩 나눠 관악산 입구 판넬 설문과 산행 중 짧은 인터뷰로 약 200명의 의견을 모았다.
- 운동 목적 중심의 초기 예상과 달리 완등의 성취감, 정상석 인증사진을 통한 기록, 하산 후 맛집 방문까지 하나의 등산 코스로 즐기는 행동을 확인했다.
- 조사 결과를 공유한 뒤 팀원 모두가 2030을 위한 기록형 등산 앱으로 방향을 정하는 데 합의했다고 제출했다.
- 20개 기능 후보를 정복지도, 클라이브, 세모피드, 산 목록의 네 가지 핵심 기능으로 좁혔다.
- 종이 초안→Figma 와이어프레임·화면정의서→Figma MCP로 Notion 기능명세서·PRD 연결의 흐름을 설명했다.
- 큐시즘 밋업 프로젝트 최우수상, 2026년 7월 iOS 출시, 월 40명대 MAU, 누적 회원 약 80명을 제출 기준으로 사용했다.
- 학회 종료 후에도 서비스를 직접 운영하며 기능 개선과 CS를 담당하고, 안드로이드 출시를 준비 중이라고 확인했다.

### 리트머스 산학협력

- 고객사가 프로젝트 진행 상황, 문서, 회의 내용, 할 일, 문의 사항을 한곳에서 확인하는 B2B 프로젝트 관리 플랫폼을 기획했다.
- IT 외주 경험자 55명 설문과 리트머스 PM 2명 인터뷰를 제출 기준으로 사용했다.
- 설문 결과는 소통의 어려움 24%, 마커형 피드백 선호 45%, 익숙한 폴더 구조 선호 54%다.
- 고객은 개발 용어를 이해하고 질문하기 어렵고, PM은 카카오톡 요청을 Notion에 다시 옮기며 여러 채널의 회의 이력을 찾는 데 시간이 드는 문제를 확인했다.
- 폴더형 문서함, 문장·단어별 마커형 피드백, 회의록 자동 요약, 홈의 프로젝트 진행 상황 기능을 기획했다.
- Figma Make로 화면 초안을 만든 뒤 대표 피드백을 반복 반영하고 디자인·개발팀에 전달했다. Figma 화면과 Notion을 MCP로 연결해 기능명세서와 화면정의서를 함께 관리했다.
- 기업 프로젝트 대상 이후 본인이 한 달간 추가 개발을 제안했고, 고객사 2곳의 시범 사용까지 완료했다고 제출했다.
- 산학협력의 기획·실행 경험이 이후 약 한 달간의 리트머스 AX 인턴으로 이어졌다.

### 텃밭닥터

- KSEB 대학연합 AI 부트캠프 640시간을 이수하고 5인 팀 PM으로 AI 병해충 진단·작물 관리 서비스를 개발했다.
- 도시농업 참여자의 96.5%가 무경험자이고 온라인 상담의 79%가 재배 관리·병해 문의라는 자료를 문제 근거로 사용했다.
- 농진청 AI 병해충 서비스를 직접 사용해 진단 후 상담까지 약 일주일이 걸리는 것을 확인했다.
- 초보 재배자가 진단 후 바로 대처하려면 방제법 확인, 추가 상담, 작물 관리까지 이어지는 흐름이 필요하다고 판단했다고 제출했다.
- PM으로 전체 아키텍처와 기술 스택을 설계하고 상담 챗봇 서버를 직접 구현했다.
- ChatGPT API가 실시간 수원 날씨를 확인하지 않고 체리 재배의 일반 답변만 제공한 문제를 확인했다. 2주간 온라인 강의·Hugging Face 자료·멘토링으로 보완했다.
- 농진청 자료의 FAISS 기반 RAG, 날씨 등 실시간 정보의 웹검색, 일반 상담의 LLM으로 세 경로를 나눴다.
- 대표 작물 5종의 벡터 DB 포함 여부에 따른 답변 차이, 영월 고추 병해 질문의 농진청 AI 답변 유사성, 맛집 추천 같은 무관 질문 차단을 검증했다.
- 앱·백엔드·병해충 진단 모델·AI 챗봇을 연동해 시연 가능한 서비스로 완성하고, 챗봇 서버를 AWS EC2에 배포했으며 Swagger로 API 문서를 정리했다.
- 최종 발표에서 진단→상담→지속 관리 흐름과 문제·해결 방식의 설득력을 긍정적으로 평가받았다.

## 직장경력 최신 제출 사실

### 쎄듀

- 보카테스트 플레이의 종이 교재 연계와 단어 학습·복습 흐름을 확인하고, 듀오링고·말해보카 등 경쟁 학습 서비스 6개를 비교했다.
- 학습 진도·성취가 보이는 홈, 햅틱·스와이프 오답 분류, 롱프레스 예문·발음 확인을 개선안으로 제안했다.
- 보카테스트 플레이와 영문법 평가 서비스를 QR 접속→문제 풀이→채점→결과 확인의 실제 학생 이용 순서로 검수했다.
- iPhone QR 카메라 실행, 학부모 인증, Safari 결제, 진도율 불일치 등을 포함해 약 30건을 찾았고 10건이 실제 개발에 반영됐다는 사용자 확정 수치를 제출했다. 출시 후에도 남은 QA 항목의 검토·반영이 이어진다고 설명했다.
- 배경 오터치로 문항이 넘어가는 문제와 연속 클릭으로 결과 화면을 놓치는 문제에는 UI·UX 개선안도 함께 전달했다.
- QA 우선순위는 주 사용자의 영향, 발생 빈도, 재현 가능성, 학습 중단 여부로 판단했다.
- 원장과 교사를 위한 교재 기반 AI 학원 운영 보조 서비스를 기획했다. 교재 진도에 맞는 과제·숙제 확인, 수업 후 진도·학생별 수행 기록, 원장의 반별 진도 확인과 수준별 반 배치·운영 판단, 담당 교사 변경 시 인수인계를 연결했다.
- 신규 서비스는 주요 사용자·핵심 기능·이용 흐름·기대효과를 발표자료로 정리해 최종 발표까지 마쳤다는 기존 사용자 확인을 유지한다.

### 리트머스 AX 교육형 인턴

- 산학협력 이후 제안을 받아 한 달간 근무했다. PM·세일즈·법무팀의 불편을 요구사항으로 정리하고 Codex·사내 에이전트 기반 프로토타입, 구현 보조, QA를 맡았다.
- PM 회의에서 세일즈가 고객사로부터 어떤 정보를 받았는지 한눈에 확인하기 어렵고, PM이 Notion·Teams·대시보드를 오가야 하는 문제를 발견했다.
- 기존 Notion에는 고객사로부터 받아야 할 정보 110개, 착수 전 확인 정보 10개, 유의사항 4개 등 총 124개 항목이 있었다.
- 124개 항목을 고객이 답변할 항목, PM이 확인할 항목, 누락돼 다시 물어볼 항목으로 나누고 Notion MCP로 프로젝트별 체크·메모 화면에 연결했다.
- Codex와 사내 에이전트가 만든 화면·코드를 직접 QA해 화면 중첩, 저장 후 제목 잘림, 완료 항목이 상단에 고정돼 미확인 항목을 가리는 문제를 찾았다. 수정 기준을 지침으로 정리해 다시 구현했고 기능은 사내 대시보드에 반영됐다.
- 승인 없는 메인 병합 경험 이후 병합 전 최소 두 차례 승인을 받도록 작업 지침을 보완했다. 기술적 강제 차단이나 재발 제로 성과로 확대하지 않는다.
- 동료 인턴과 신설 법무팀의 계약서 추적·프로젝트별 위험 관리 기능을 맡았다. 1차 미팅 전 작동형 프로토타입 초안을 준비하고, 리스크 등급·분쟁 기록·NDA 만료 알림·개인정보 취급 및 파기 일정으로 기능을 나눠 피드백을 반영했다.
- 법무 기능의 개인 역할은 요구분석·프로토타입·구현 보조다. 전체 기능을 단독 개발했다고 확대하지 않는다.

### 인크루트

- 자율주행 AI 학습용 교통 표지판(TSR)·신호등(TLR) 이미지 3,000장 이상을 라벨링하고 해외 외주사의 1차 작업 데이터를 검수했다.
- 국가별 표지판 차이, 객체 가림처럼 판단이 모호한 사례를 모아 팀·외주사와 분류 기준을 맞췄다.
- 데이터 이동 중 파일 혼선을 줄이기 위해 폴더 정리 방식을 공유했다.
- 내부 ERP에 자동 게시된 채용 공고의 중복, 신입·경력 구분, 수정·거절 필요 여부를 재검수하고 Google 스프레드시트에 결과를 기록했다.
- 서비스기획 직무와의 직접 적합도는 상대적으로 낮아, 향후 지원서에서는 데이터 품질 기준과 모호한 사례 조율 경험 중심으로 짧게 활용한다.

## 재사용 주의

- 세모산의 공식 프로젝트 기간과 이후 서비스 운영 기간을 구분한다.
- 리트머스 산학협력 추가 개발과 AX 교육형 인턴은 연속된 경험이지만 기간과 역할이 다른 별도 항목이다.
- 리트머스 산학협력 팀 인원은 기존 5명 기록과 이번 제출의 8명 진술이 충돌한다. 소프티어 제출에는 8명을 사용했으나, 다른 지원서에서 인원을 쓸 때는 사용자에게 다시 확인한다.
- 쎄듀의 개선안 3개는 제안이며 전부 개발됐다고 쓰지 않는다. 약 30건 중 10건 반영과 구분한다.
- AX 인턴의 124개는 기존 업무 확인 항목 수다. 자동 생성 수, 누락 감소율, 시간 절감량으로 바꾸지 않는다.
