# SK브로드밴드 자소서 작성 과정의 경험 업데이트

기준일: 2026-10-14. 출처는 사용자 대화·최종 자소서 정정이다. 회사·로그·수상증의 독립 인증과 구분한다. 과거 자소서 원문은 보존하되, 새 지원서 집필에는 최신 역할·측정 범위·조건을 우선한다. 기업별 포부는 미래 계획이며 실제 경험으로 저장하지 않는다.

## 리트머스 기업 프로젝트

- 백오피스 관심과 경영정보학 복수전공을 배경으로 PM·고객사 소통 플랫폼 기획에 참여했다. 기획 담당이며 팀 전체 개발을 단독 수행한 것으로 쓰지 않는다.
- PM 2명과 IT 외주 경험 고객 50명을 조사해 분산된 소통 채널과 IT 용어 이해·질문의 어려움을 파악했다. 조사 방식·응답 비율은 미확인이다.
- 처음부터 고객사 한 곳 이상이 실제 소통에 사용하는 것을 목표로 삼았다. 회의록 보관함은 파편화된 기록 추적, 문장·단어별 질문은 이해하지 못한 부분의 질문 편의를 위해 설계했다. 자동 요약·문장별 질문은 정규 기간에 팀이 구현했고 이후 고객사 사용 단계에서도 사용됐다고 확인했다.
- 약 한 달의 정규 프로젝트·시험기간으로 실제 도입까지 못했으나 팀은 기업 프로젝트 대상을 받았다. 대표에게 추가 개발 한 달을 제안했고 후속 약 4주 AX 교육형 인턴으로 출퇴근했다. 추가 개발과 인턴을 하나의 한 달로 합치지 않는다.
- 팀 플랫폼과 현업 흐름이 맞지 않았다. 기존에는 없던 프로젝트별 단계 설정이 추가 관리 부담이었다. 단계 설정을 빼고 홈에 Figma·개발 서버를 임베드해 결과물을 바로 보는 방안을 제안했다. 사내 대시보드 연동은 점진적 확대 방향이다. 제안과 실제 반영 범위를 구분한다.
- 서로 다른 고객사 두 곳의 시범 사용을 확인했고 본인 계약 종료 후에도 정식 사용 중이라고 설명했다. 본인 계약 종료를 고객사 계약 종료로 해석하지 않는다. 현재 활성 고객 수는 별도 미확인이다.
- PM은 기존 5개 초과 채널을 사용 시 1~2개로 줄일 수 있다고 예상했다. 실제 감소·절감률로 바꾸지 않는다.
- 팀원 8명이라는 최신 설명과 기존 5명 기록이 다르므로 전체 인원은 확인 전 빼고 쓴다. 베타 시점도 이전 6월 초·AX 후반 설명 차이가 있어 정확한 날짜를 확정하지 않는다. 개인 기여율 미확인.

재사용 에피소드: **LT-Q1 실제 사용 목표를 수상 이후 도입까지 이어간 경험**. 상황·최초 목표→양측 조사·MVP→기간 제약→연장 제안·현업 흐름 수정→고객사 두 곳 시범 사용. 수상과 실사용은 다른 결과다.

## 리트머스 AX 교육형 인턴

- 담당은 요구분석·기획·AI 기반 프로토타입·구현 보조·QA다. 기간은 기존 확정 2026.04.20~05.15, 약 4주. 일부 과거 자소서의 두 달 표현을 재사용하지 않는다.
- PM 회의에서 세일즈→PM 고객사 인계 시 어떤 정보까지 받았는지 체계적으로 정리되지 않는 문제를 파악했다. 우선 Notion 체크리스트를 대시보드에 연결해 관리하는 방향을 정했다. 결제 시스템·소통 담당자 등 기존 체크리스트 약 124개 항목을 프로젝트별 체크·메모 화면에 연결했고 기능이 사내 대시보드에 반영됐다.
- 사용 도구는 Codex·사내 에이전트 중심이다. 이 사건에 Claude Code를 사용했다고 쓰지 않는다. 회사 지원·코드 생성 용도·비용을 고려했다. 역할별 에이전트를 여러 터미널에서 기능 개발·버그 수정에 병렬 활용했다. Notion MCP는 원문 접근·연결 수단이다.
- AI가 틀·코드를 작성한 뒤 본인이 직접 사용·QA했다. 화면 중첩, 저장 후 제목 잘림, 완료 항목 고정으로 확인할 항목이 가려지는 문제를 찾아 수정 기준을 지침으로 정리했다.
- 승인 없는 메인 병합 경험 이후 병합 전 최소 두 차례 승인을 받도록 스킬 지침을 보완했다. 기술적 강제 차단·재발 제로·효율 향상을 입증한 것으로 쓰지 않는다.
- 동료 인턴과 법무 계약 추적·위험 관리 프로토타입·구현 보조를 수행했다. 실제 위험수준 알림 누락을 확인한 사례는 법무 과제이며 PM 체크리스트 성과로 합치지 않는다.
- 124개는 업무 확인 항목 수다. 자동 생성 개수·누락률 감소·절감 시간으로 바꾸지 않는다.

재사용 에피소드: **AX-Q4 AI로 구현하되 현업 사용성 기준을 직접 제시한 경험**. 인계 정보 미체계화→우선 기존 자료 연동→도구 선택·역할 분담→직접 QA·수정 기준→대시보드 반영. 법무 에피소드는 별도 유지.

## 학생회 AI 마스코트

- 문헌정보학과 학생회 정책부 팀장. 기존에는 예산을 들여 외주 제작하는 방식이 일반적이었고 1차 외주 시안을 실제 받았다. 외주를 전혀 하지 않았다고 쓰지 않는다.
- 책 먹는 여우 시안이 어둡고 딱딱해 다양한 활동을 하는 학과라는 슬로건보다 책·도서관에 한정된 이미지를 고착시킬 수 있다고 본인이 판단했다.
- 학과동 앞 길고양이 두 마리에서 도서관을 지키는 따뜻한 캐릭터를 구상했다. 두 성격·과잠바 남색·고양이 주황/하양·책을 지니는 설정과 한 마리의 머리 위 책 포즈로 정체성을 담았다. 실제 고양이가 책을 들고 다닌다는 뜻이 아니다.
- GPT·DALL-E로 색상·성격·포즈를 구체화해 약 10차례 생성·수정했다. 직접 3D 모델링 수행 여부는 미확인이다.
- 키링·띠부띠부 스티커·유리잔에 활용됐다. 본인은 스티커 의견·유리잔 제작에 참여했다. 이름 공모전도 개최해 이름 결정에 학생 참여 기회를 마련했다. 문화 통합·협력 향상 측정값은 없다.
- 2026년 올해 게시글 현재까지 25개 중 11개에 활용됐다. 44%는 활용 비중이지 증가율·참여율이 아니다. 계정 이름·집계 종료일 미제공이며 연말 총량이 아니다. 현재 공식 마스코트이고 교내 유일한 학과 마스코트 보유 학과라는 사용자 확인. 독립 비교조사나 교내 최초로 확대하지 않는다.
- 코로나 전후 업로드·이벤트 증가를 마스코트의 인과 성과에서 제외한다. 기존 ‘2년째’는 옛 자소서 시점 기준이며 기간을 자동 늘리지 않는다.

재사용 에피소드: **ST-Q2 외주·예산·시안의 한계에서 AI 제작을 자발적으로 제안한 경험**. 문제 인식→새 방식 제안→학과 맥락으로 콘셉트·프롬프트 구성→약 10차례 수정→굿즈·게시글·이름 공모전 확장.

## 세모산

- 등산 앱 10인 팀 PM. 팀원 대부분 등산 문화를 낯설어했다. 개발자는 기존 이용자가 많은 4050으로 주타깃 변경을 제안했고 본인은 2030 수요에 주목했다.
- 자료만으로 실제 수요를 충분히 알기 어렵고 직접 경험으로 가정을 검증하고자 팀원 9명과 관악산에 올랐다. 약 200명의 현장 인터뷰로 2030 수요·산행 기록·완등 성취·하산 후 맛집/막걸리까지의 코스를 확인했다. 최신 자소서는 200명을 2030으로 쓰지만 과거 기록은 전체 등산객으로도 표기한다. 전원 연령을 독립 확인한 것은 아니다.
- 본인도 운동·체력·다이어트 중심 가정에서 기록·성취·하산 후 활동의 중요성을 받아들였다. 현장 확인을 바탕으로 2030 타깃에 팀이 합의했다. 내 의견으로 상대를 이긴 이야기보다 본인 변화·의견 수용을 중심으로 쓴다.
- 개발자의 가벼운 추천 제안을 받아 온보딩 6문항→3문항으로 줄이고 30초 이내 산 추천을 목표로 구성했다. 코스까지 정확히 추천하는 방식에서 산 정도를 가볍게 추천하도록 바꿨다. 30초는 구성 목표이며 실측값 미확인.
- 하산 후 맛집 자동 추천 제안에는 BM 확장 가능성을 검토하고 산행 난이도 평가 화면에 추천을 추가할 수 있는 구조의 디자인을 요청했다. 자동 추천 구현 완료·매출로 확대하지 않는다.
- 산별 시설 정보가 통일되지 않아 백엔드 수집·디자인 표시가 어려웠다. 본인은 데이터를 확인해 화장실/편의점까지 필수였던 정책을 필요한 항목 중심으로 수정하고 누락 시설 정보는 AI로 공식 산 자료를 수집·추출하는 구조를 제안했다. 정보 누락과 시설 부재를 구분한다. 제안의 구현·합의 결과는 미확인.
- 최신 사용자는 방향이 불분명한 20개 기능→핵심 4개를 확인했다. 과거 10개 기록과 단계 차이는 미확정이므로 옛 10개를 새 자소서에 자동 재사용하지 않는다.
- 팀은 밋업 프로젝트 최우수상, 앱 출시, 현재 약 70명 회원 사용을 설명했다. 기준일은 이번 준비 시점으로 활성/누적 가입 정의는 미확인. 사용자 추정 개인 기획·조율 기여도 약 70%, 팀 전체 코드 개발의 70%로 확대하지 않는다.

재사용 에피소드: **SM-Q3 공동 산행으로 서로 다른 관점을 받아들이고 공동 방향을 정한 경험**. 타깃 차이→현장 검증→본인 인식 변화·팀 합의→추천 축소·맛집 제안 반영→20개를 4개로 집중·팀 수상. **SM-DATA 시설 데이터와 디자인 표시 기준을 조정한 사례**는 별도 보조 에피소드.

## 인플레이스

- PM으로 반복 탐색 고객의 편의와 API 비용을 비교했다. 건별 과금의 부담·무제한 구독의 원가 위험을 검토해 저장 데이터 기반 기능은 구독, 호출 비용 발생 기능은 크레딧이라는 혼합 모델을 설계했다.
- 사용자 1,000명·월 서버비 100,000원·VAT 포함 정상가 29,900원·결제 수수료 3.3%·월 AI 비용 여유분 80원 가정. VAT 제외 27,181.82원, 수수료 986.70원, 해당 비용 차감 후 26,115.12원. 서버비 충당 3.829명→정수 4명, 같은 모집단 가정 전환 0.4%다.
- 인건비·마케팅비·관리비와 무료 사용자의 AI 호출 등 원가 범위는 미확정. 사업 전체 손익분기점·실제 수익 실현이라고 쓰지 않는다. 월 80원의 호출 횟수·사용자당 사용량 산정도 미확정이다.
- GPT-4o 호출 7.5~20원, 환율 1,500원, 입력 1,000~4,000·출력 250토큰은 사용자 추정. GPT-5 가격 소개 링크는 GPT-4o 요율 근거로 쓰지 않는다. 토큰 증가와 서버비 증가 조건을 비교했고 실제 비용은 계속 확인해야 한다고 판단했다.
- 얼리버드 서버비별 유료 사용자 12/35/59/117명 표는 얼리버드 가격·비용 조건 미제공이라 재계산 확정하지 않는다. ROI와 서버비 충당 기준을 구분한다.
- 기존 GA4 16→32명 기능 진입은 기간·페이지·사용자 정의 동일 여부 미확인, 가입 7명/20명은 범위 충돌이다. 수익·전환율 개선으로 임의 통합하지 않는다.

재사용 에피소드: **IF-Q5 사용자 편의와 원가를 비교해 과금 정책을 구체화한 경험**. 대안 비교→비용 가정→정상가·서버비/토큰 변화 검토→추정과 실제 수익 구분→운영 가능한 정책. 계산 수치는 시뮬레이션이다.

## 도서관 빅데이터 공모전

- 코드와 유사도 추천 로직은 팀원이 작성·설계했다. 본인은 파이프라인·유사도 기반 추천을 학습하고 Jupyter Notebook에서 팀원 코드로 독립서적 크롤링을 보조했다.
- 필수 데이터인 도서관 정보나루 API의 월별 인기도서 키워드와 인디도서 설명을 활용한 추천 방향을 이해했다. 기획 배경 조사·콘텐츠·와이어프레임 제작이 본인 핵심 역할이다.
- 2,085건→1,454건 정제와 추천 로직은 팀 산출물이다. 본인이 전부 정제하거나 모델을 단독 설계했다고 쓰지 않는다. 기존 개인 기술 주도 표현과 상충할 때 이 최신 역할 구분을 우선한다.
- 팀은 국립중앙도서관 빅데이터 공모전 1차 합격·최종 발표, 최종 수상은 아님. 팀 인원 4/5명 기존 기록 충돌로 인원은 확인 전 제외.

재사용 에피소드: **LB-LEARN 데이터 수집·추천 방법을 이해해 기획·콘텐츠·와이어프레임으로 구체화**. 분석 모델 단독 개발 성과로 사용하지 않는다.

## 교통 데이터 분석

- 이전 ‘수행 거의 없음’ 설명은 후속 답변에서 약 30% 기여로 수정됐다. 비중은 자기 추정치이며 정확한 계량 기여가 아니다.
- 본인 담당: R 분석·그래프 시각화·상관관계·군집분석 적용·도표·보고서 작성·전반 관계 해석. 지도 시각화·전체 방향 등 팀원의 역할과 구분한다.
- 민원 자료 2022.01~12, 인구밀도·이동량 2021~2023, 서울 실시간 혼잡도·도로 소통 2023.10 2주, CCTV 2018.11~2023.04. 다른 기간 자료를 동일 시계열로 비교하거나 인과 증거로 취급하지 않는다.
- 위반 유형은 불법 유턴·정지선 침범·중앙선 침범. 관악구·금천구·마포구 등에서 CCTV 분포와 민원·사고 지역을 비교했고 팀은 실제 거리 지점에 대한 교통안전 개선안을 제안했다.
- CCTV와 민원의 관계 방향·계수·유의성·노출 통제는 미제공. CCTV 설치가 민원을 감소시켰다거나 검증된 사고 예측 성능·정책 실제 설치 효과를 주장하지 않는다.

재사용 에피소드: **TR-Q5 여러 교통 지표를 관계 분석·시각화하고 개선안 근거로 정리**. 본인 분석→도표·보고→팀 개선 제안. 새로 익힌 방법의 강의/교재 경로는 미확인이라 만들지 않는다.

## 텃밭닥터

- PM으로 초보 사용자가 진단 이후 다음 행동을 정하기 어려운 문제에서 진단·상담·관리 흐름을 기획했다.
- 구현 이해의 한계를 보완하고자 2주 온라인 강의·Hugging Face 자료·멘토링으로 학습했다. 전문지식은 자료 검색/RAG, 실시간 정보는 웹검색, 일반 상담은 LLM으로 답변 경로 구분. 질문별 응답과 예외를 팀원과 점검하고 최종 시연했다.
- WBS·마일스톤·업무 진척 관리·발표·보고서·서비스 구조 정리 역할이 있다. 기존 기록의 구현 범위를 새로운 수상 프로젝트와 혼동하지 않는다.
- **캡스톤 디자인 및 AI 해커톤 경진대회 AI 알고리즘 활용 분야 장려상은 텃밭닥터가 아니다. STT→Task→To-do 프로젝트 수상이다.** 텃밭닥터에 이 수상을 붙이지 않는다.

재사용 에피소드: **GD-Q5 기술의 가능성·제약을 학습해 실행 가능한 서비스 기획으로 연결**. 전략기획 지원에서는 코드/기술명 나열보다 기획 판단·학습·검증·실행 계획을 설명한다. 수치 정확도·상담시간 개선은 측정 근거 없음.

## STT AI 해커톤

- 담당 5인 팀 PM·리드. 캡스톤 디자인 및 AI 해커톤 경진대회 **AI 알고리즘 활용 분야 장려상**이라는 최신 사용자 수상 표현.
- 사용자 문제·핵심 기능·사용 흐름 정의, 음성 입력→STT 변환→AI 기반 Task 세분화→To-do 생성 프로토타입 흐름 기획.
- 서비스 타깃·수익모델(BM) 구체화, 마일스톤·업무 분배·진척 관리, 기획 배경·핵심 기능·BM을 구조화한 최종 발표자료 제작.
- 텃밭닥터·빙고 공모전과 별개 프로젝트. 직접 STT·AI 알고리즘 코드 구현 또는 모델 개발로 기여를 확대하지 않는다. 전체 기여율 미확인.

재사용 에피소드: **AH-PM AI 기능을 사용자 흐름·타깃·BM과 실행 계획으로 구체화**. 수상 설명에서는 본인 기획·관리·발표 역할과 팀 수상을 구분한다.
