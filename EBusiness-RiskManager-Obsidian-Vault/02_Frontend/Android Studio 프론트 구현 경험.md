# Android Studio 프론트 구현 경험

## 경험 요약

[[리스크 매니저]]는 Android Studio를 활용해 앱 프론트를 구현해본 교내 수업 과제다. 본인은 프론트 구현의 약 80%를 맡았고, 기획된 사용자 흐름을 실제 앱 화면으로 옮기는 역할을 했다.

80%로 정리한 이유는 전체 화면과 사용자 흐름은 대부분 직접 구현했지만, 내부 로직 수정 약 10%, QA 및 수정 약 10%는 팀 차원의 보완 과정으로 진행됐기 때문이다.

## 사용 기술

- Android Studio
- Kotlin
- 앱 화면 구성
- 사용자 입력 흐름 구현
- 결과 화면 구성
- 실제 기기 연결 시연

프로젝트 전체 구조에는 Python API Server, Gemini API 같은 요소가 포함되어 있었지만, 본인 경험으로 정리할 때는 Android Studio 기반 프론트 구현 경험으로 설명하는 것이 정확하다.

## 구현한 역할

- 기획 흐름을 앱 화면 단위로 나누기
- 아이디어 입력 화면 구성
- 추가 질문 및 답변 흐름 구성
- 분석 결과를 사용자가 이해할 수 있게 화면으로 표현
- RPN 결과와 리포트 확인 화면 구성
- 용어 설명, 참고 링크 등 보조 정보 화면 구성
- 발표와 시연에서 설명 가능한 흐름으로 화면 정리
- 실제 기기에서 시연 가능한 상태로 흐름 점검

## 구현에서 중요했던 점

### 처음 접한 앱 개발 환경에 적응하기

앱 개발과 프론트 구현 모두 처음 도전한 영역이어서 Android Studio 세팅 단계부터 시간이 많이 걸렸다. 플러그인 AI를 설치해 환경 세팅과 구현 과정에서 참고할 수 있게 만들었고, 이를 통해 낯선 개발 환경에 적응했다.

### 기획을 화면으로 번역하기

이 프로젝트의 핵심은 복잡한 분석 개념을 사용자가 따라갈 수 있는 화면 흐름으로 바꾸는 것이었다. FMEA나 RPN처럼 낯선 개념을 바로 노출하면 사용자가 어렵게 느낄 수 있기 때문에, 입력-질문-결과-설명 순서로 흐름을 쪼개는 것이 중요했다.

### 결과 화면의 이해 가능성

분석 결과는 숫자와 텍스트가 함께 제공되는 형태였다. 따라서 단순히 값을 보여주는 것보다, 사용자가 “이 점수가 왜 중요한지”를 이해할 수 있도록 결과 화면과 설명 영역을 함께 고려했다.

### 수업 과제 범위 내 구현

상용 수준의 Android 앱 개발이라기보다는, Android Studio로 기획된 앱 화면과 주요 흐름을 구현해본 경험이다. 취업 문서에서는 “Android Studio 프론트 구현 경험”과 “기획을 앱 UI로 구현한 경험”으로 표현하는 것이 적절하다.

## 시연 결과

최종 발표에서는 에뮬레이터에만 의존하지 않고 실제 기기를 연결해 시연했다. 따라서 이 경험은 정적인 화면 설계가 아니라, 실제 앱 화면 흐름을 기기에서 확인하며 구현한 경험으로 정리할 수 있다.
