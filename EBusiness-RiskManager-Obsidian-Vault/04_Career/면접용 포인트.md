# 면접용 포인트

## 한 문장 설명

교내 E비즈니스 수업에서 Android Studio와 Kotlin을 활용해 비즈니스 리스크 분석 앱의 프론트 화면과 사용자 흐름을 구현했고, 발표자료를 전담해 기획 의도와 구현 결과를 설득력 있게 정리했다.

## 강조하기 좋은 역량

- Android Studio를 활용한 앱 프론트 구현 경험
- Kotlin 기반 화면 구현 경험
- 기획 내용을 앱 화면과 사용자 흐름으로 전환한 경험
- FMEA/RPN 같은 분석 개념을 사용자 친화적인 화면으로 풀어낸 경험
- 발표자료를 전담하며 프로젝트 메시지를 구조화한 경험
- 처음 접한 앱/프론트 개발 환경에서 AI 도구를 활용해 세팅과 구현에 적응한 경험
- 실제 기기를 연결해 앱 흐름을 시연한 경험
- 창업 수요 증가라는 시장 흐름을 읽고 서비스 문제 정의로 연결한 경험
- AI 기반 서비스에서 신뢰도 확보 방식을 고민한 경험

## 피드백

교수님 피드백에서는 기획의 의도가 좋고, 창업을 새로 시작하려는 수요가 늘어나는 상황에서 시장성을 잘 파악했다는 평가를 받았다. 또한 AI 기반 분석 서비스에서 신뢰도 측면을 많이 고민한 점이 느껴진다는 피드백도 있었다.

## 직무별 활용 방향

### 프론트엔드/앱 개발

Android Studio로 앱 화면을 직접 구현해본 경험으로 사용할 수 있다. 다만 상용 앱 배포 경험보다는 수업 과제 기반의 프론트 구현 경험으로 표현하는 것이 정확하다.

예시 표현:

> Android Studio와 Kotlin을 활용해 비즈니스 리스크 분석 앱의 주요 화면과 사용자 흐름을 구현했습니다. 분석 개념이 복잡한 서비스였기 때문에 입력, 질문, 결과, 설명 화면으로 흐름을 나누어 사용자가 단계적으로 이해할 수 있도록 구성했습니다.

보강 표현:

> 전체 프론트 구현의 약 80%를 담당했고, 나머지 20%는 내부 로직 수정과 QA 과정에서 팀 단위로 보완했습니다. 최종 발표에서는 실제 기기를 연결해 앱 흐름을 시연했습니다.

### PM/서비스 기획

문제 정의에서 화면 구현까지 연결한 경험으로 사용할 수 있다. 특히 초기 환경 앱 아이디어에서 리스크 분석 앱으로 피벗한 과정, FMEA를 서비스 기능으로 변환한 과정, 발표자료를 전담한 점을 강조할 수 있다.

예시 표현:

> 막연한 창업 리스크를 정량적으로 점검할 수 있는 앱을 기획하고, FMEA 기반 RPN 구조를 사용자 흐름에 맞게 설계했습니다. 이후 발표자료를 전담해 문제 정의, 기능 흐름, 구현 결과가 일관되게 전달되도록 정리했습니다.

보강 표현:

> 초기 위험도 측정 로직이 다양한 창업 맥락을 충분히 반영하지 못한다고 보고, 업종별 질문과 가중치를 먼저 적용한 뒤 RPN을 산출하는 방향으로 고도화했습니다.

피드백 기반 표현:

> 창업을 새로 시작하는 수요가 늘고 있다는 시장 흐름을 바탕으로, 예비 창업자가 아이디어의 리스크를 사전에 점검할 수 있는 서비스로 문제를 정의했습니다. 발표 후에는 기획 의도와 시장성 파악이 좋았다는 피드백을 받았습니다.

### UX/UI

어려운 분석 개념을 초보자도 따라갈 수 있는 화면 흐름으로 바꾼 경험으로 사용할 수 있다. 용어 설명, 참고 링크, 단계별 질문 구조를 넣은 점이 강점이다.

예시 표현:

> FMEA와 RPN처럼 낯선 분석 개념을 사용자가 이해할 수 있도록 입력-질문-결과-설명 흐름으로 나누고, 용어 설명과 참고 링크를 함께 제공하는 UI를 구성했습니다.

보강 표현:

> 위험도 결과에서 사용자가 다음 행동으로 넘어가지 못하는 지점이 있다고 보고, 창업지원센터 등 외부 지원 경로로 연결되는 사용자 여정을 함께 고려했습니다.

### AI/AX 활용

이 프로젝트는 AI API를 직접 깊게 개발한 경험으로 말하기보다는, AI 분석 결과를 사용자가 신뢰할 수 있는 제품 흐름으로 만드는 고민으로 설명하는 편이 좋다.

예시 표현:

> AI 응답의 신뢰성을 높이기 위해 Cold Start, 낙관/비관 페르소나, 끊어서 생각하기 구조를 적용한 분석 흐름을 설계했습니다. 단일 답변을 그대로 보여주는 대신, 서로 다른 관점의 분석과 최종 합의 리포트를 통해 사용자가 결과를 더 신뢰할 수 있도록 구성했습니다.

피드백 기반 표현:

> AI가 제안하는 분석 결과를 사용자가 그대로 믿어야 하는 구조가 되지 않도록, 낙관/비관 페르소나와 단계별 사고 흐름을 넣어 신뢰도를 보완했습니다. 이 부분은 신뢰도 측면을 많이 고민한 것이 느껴진다는 평가를 받았습니다.

## 주의할 점

- 백엔드나 Gemini API 구현을 본인이 주도했다고 표현하지 않는다.
- 이 경험은 “Android Studio 프론트 구현 경험”으로 정리하는 것이 가장 정확하다.
- 프로젝트 전체 기술 스택에는 Python API Server와 Gemini API가 포함되어 있었지만, 본인의 직접 기여는 프론트 구현, PPT, 일부 보고서 작성, 위험도/AI 신뢰성 흐름 고도화에 대한 기획적 보완 중심으로 말한다.
