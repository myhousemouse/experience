# 위버스 자소서 에피소드

연결 경험: [[위버스 앱 개선 프로젝트]]. 출처: 사용자 최종 PPT·설문 XLSX·Notion MD·리뷰 코드 정리·UI ZIP 및 2026-10-15 역할 확인. [상세 역할](../03_본인기여_자소서에피소드.md).

## WV-01 — 사용자 의견을 팬레터 수정 안내로 구체화

- 상황: 금칙어 안내만으로 수정 위치를 찾기 어려웠던 당시 팬레터 UX.
- 본인 행동: 리뷰 코드 작성·크롤링, 설문 설계/진행, 버블 비교. 조사한 불편을 보내기 후 경고·문제 표현 빨간색 표시의 프로토타입으로 구체화.
- 근거: 전체 설문 138건과 상세 불편 36/63을 구분. PPT 17·PNG 3상태.
- 결과: 클릭 가능한 Figma 프로토타입·발표 산출. 수정 편의·이탈 가능성 감소는 기대효과.
- 재사용 관점: VOC→문제 정의→다른 서비스 비교→수정 안내 흐름 설계. 실제 운영 정책 배포·성공 전송률 향상으로 바꾸지 않는다.

## WV-02 — 번역의 이해 장벽을 보충 설명·평가 UI로 개선 제안

- 상황: 2024년 사투리·유행어의 오역 사례로 팬 이해가 어려울 수 있었음.
- 본인 행동: 리뷰·설문 근거와 커스텀 GPT 결과를 참고해 어절별 설명과 평가 UI 제안·Figma 프로토타입 작성.
- 근거: 사진 제시 번역 불편 38/63, PPT 20·번역 전/설명/평가 선택 화면.
- 결과: 클릭 가능한 설명·평가 흐름을 구체화한 산출물. 오역 감소·소통 장벽 완화는 기대효과다.
- 재사용 관점: 글로벌 사용자 이해를 지원하는 개선 제안. 실제 GPT API 구현·자동 학습·정확도 향상을 주장하지 않는다.

## 공통 검증 메모

1~2점 불만/4~5점 만족 분류가 확인되지만 수집 코드의 별점 필터는 없음. 분류 개수 합계 1,088은 고유 리뷰 수가 아니다. 설문 분모·사용 경험 불일치와 조사 기간 차이는 원본 검토에 기록했다. 팀 피드백 발췌는 개선 전후·11/20~22 기록이지 특정 의견자·수정 계기를 입증하지 않는다. 공식 수상·개선 수치·현재 기능 문제로 확대하지 않는다.
