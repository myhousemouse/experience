    ### 위버스

    위버스는 ‘우리(We)’와 ‘우주(Universe)’의 합성어로, 하이브(HYBE)의 자회사인 위버스 컴퍼니(Weverse Company)에서 개발․운영하는 팬 플랫폼이다. 이름처럼 아티스트와 글로벌 팬이 함께 만들어가는 공간이며, 아티스트가 직접 남긴 이야기에 직접 반응하고 다른 팬들과도 소통이 가능하다. 기본적으로는 무료이나, ‘멤버십 온리(Membership Only) 콘텐츠(음성, 동/영상 등)’는 입점 아이돌의 글로벌 오피셜 팬클럽 멤버십에 유료로 가입해야 이용 가능하다. 기존 팬클럽 정회원과 유사하게, 앨범 구매, 티켓팅(금액 할인 혹은 예매 기간 오픈), 굿즈 구매, 콘텐츠 공개 일시 등에서 유료 회원들에게 조금이나마 우선권을 준다. 커머스 행위는 별도로 마련된 위버스샵을 통해 이루어진다. 아티스트의 댓/글 작성에 대한 푸시 알림, 아티스트에게 알리고 싶지 않은 글 숨기기, 외국어(영어, 중국어, 일본어 등) 자동 번역 등 다양한 커뮤니케이션 기능을 보유했다(위버스 홈페이지 및 앱 참고).

    ### 버블

    bubble은 아티스트와 메시지를 1:1 채팅방으로 수신하고 수신한 메시지에 답장을 보낼 수 있는 월구독형 자동갱신 프라이빗 메시지 서비스이다. 팬들은 메시지 수신을 원하는 그룹을 선택한 후 원하는 멤버 수만큼 구독권을 결제하고 아티스트를 선택하면 해당 아티스트로부터 수시로 텍스트와 이모티콘뿐만 아니라 음성메시지, 사진, 동영상을 수신할 수 있다. Lysn을 통해 공개되어 이전에는 Lysn에 입점한 스타만 이용할 수 있었지만, 이후 다른 소속사나 배우 등 다방면으로 늘려 서비스를 제공하고 있다. 매달 4,500원을 내고 아티스트와의 채팅을 구매하는 방식으로, 구독한 날부터 기념일이 시작되며 아티스트가 보낸 마지막 메시지를 기준으로 총 3회 답장을 보낼 수 있다. 구독 기념일마다 답장 가능한 글자 수가 추가되며 다음 구독 기념일까지 해당 혜택이 유지된다.

        ### [라이브 방송 다시보기 기능 개선]

        아티스트의 라이브 방송을 다시보는 경우, 방송의 내용이 궁금해서 다시 보는 경우도 있지만 라이브 방송에 들어온 다른 멤버가 아티스트 및 팬들과 소통하며 어떤 댓글을 달았는지 궁금해 하는 경우가 있어 다시보는 경우가 있다. 그러나 라이브 방송을 다시 보려면 처음부터 방송을 재생하며 아티스트가 대략적으로 언제쯤 댓글을 달았는지 하나하나 찾아내야 한다는 불편함이 있다.

        오른쪽 사진처럼 아티스트의 라이브 방송이 시작한 시간을 기준으로 댓글을 단 시간이 표시되는 것이 아닌 라이브 방송이 송출되는 시간을 기준으로 타임스탬프가 찍힌다.

        이를 개선하기 위해 라이브 방송이 송출되는 시간을 기준으로 하는 것이 아닌 라이브 방송이 시작한 시간을 기준으로 (예. + 13:35) 표시하는 방법이 있다.

        또는 재생 바에 아티스트의 채팅이 올라온 부분을 표시하거나 타임스탬프를 클릭해 팬들이 클릭 한번만으로도 아티스트의 댓글이 올라온 때와 방송 내용을 함께 볼 수 있도록 하는 방법이 있다.

        ```python
        import requests
        import pandas as pd
        from datetime import datetime

        # 앱 ID와 국가 설정
        app_id = "1456559188"  # App Store ID
        country = "kr"  # 국가 코드

        # 날짜 범위 설정 (Naive datetime)
        start_date = datetime(2021, 1, 1)  # 시작 날짜
        end_date = datetime(2024, 11, 1)  # 끝 날짜

        # URL 템플릿
        base_url = f"https://itunes.apple.com/{country}/rss/customerreviews/page={{page}}/id={app_id}/sortby=mostrecent/json"

        # 데이터 저장용 리스트
        reviews = []

        # 페이지 반복
        for page in range(1, 11):  # 최대 10페이지 크롤링
            url = base_url.format(page=page)
            response = requests.get(url)

            if response.status_code != 200:
                print(f"Error fetching page {page}: {response.status_code}")
                break

            data = response.json()
            if "feed" not in data or "entry" not in data["feed"]:
                print(f"No reviews found on page {page}")
                break

            for entry in data["feed"]["entry"]:
                if isinstance(entry, dict):
                    reviews.append({
                        "userName": entry.get("author", {}).get("name", {}).get("label", "Unknown"),
                        "rating": int(entry.get("im:rating", {}).get("label", 0)),
                        "title": entry.get("title", {}).get("label", ""),
                        "content": entry.get("content", {}).get("label", ""),
                        "date": entry.get("updated", {}).get("label", "")  # 원본 날짜
                    })
            print(f"Page {page} fetched successfully.")

        # 날짜 필터링 (Naive datetime 사용)
        filtered_reviews = []
        for entry in reviews:
            try:
                # 타임존 정보가 있는 datetime 객체 생성
                review_date = datetime.fromisoformat(entry["date"])

                # 타임존 제거 (Naive datetime으로 변환)
                review_date_naive = review_date.replace(tzinfo=None)

                # 날짜 범위 확인
                if start_date <= review_date_naive <= end_date:
                    filtered_reviews.append(entry)
            except Exception as e:
                print(f"Error parsing date: {entry['date']} - {e}")

        # 데이터프레임 생성
        df_reviews = pd.DataFrame(filtered_reviews)

        # 저장
        csv_filename = f"appstore_reviews_{app_id}_filtered.csv"
        df_reviews.to_csv(csv_filename, index=False, encoding="utf-8-sig")
        print(f"Filtered reviews saved to {csv_filename}")
        ```

            **3단계: 시장환경 및 경쟁환경 조사**

            구글 캘린더와 같은 일정 관리 앱, 그리고 팬 커뮤니티의 소식 알림 시스템을 조사하여 차별화 포인트를 찾습니다. 팬들이 원하는 콘텐츠와 기능을 세분화하여 캘린더 형식으로 맞춤 제공하는 방안을 모색합니다.

            **4단계: 디자인(스토리보드) 구성**

            “팬 캘린더” 기능을 추가하여 사용자가 선호하는 아티스트나 관심사를 선택하면 관련 일정과 뉴스가 자동 업데이트됩니다. UI는 월별 캘린더 형태로 제공되며, 중요한 일정에 대한 알림 기능을 추가하여 팬이 놓치지 않도록 합니다.
