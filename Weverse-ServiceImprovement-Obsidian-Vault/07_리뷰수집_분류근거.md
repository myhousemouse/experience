# 리뷰 수집과 분류 근거

출처 R01: 사용자 업로드 텍스트. 코드는 직접 작성했다는 U02와 함께 읽는다. 코드 내용은 확인했고 실행 로그·리뷰 CSV·분류 코드는 미제공이다. 실제 수집 결과와 분류 재현은 독립 검증하지 않았다. [사용자 원문](근거/리뷰수집코드_분석정리_사용자원문.md)

## 수집 조건

| 항목 | Google Play | App Store |
|---|---|---|
| 대상 | `co.benx.weverse` | 앱 ID `1456559188` |
| 도구 | google_play_scraper, pandas | requests, pandas, RSS |
| 언어·국가 | `lang=ko`, `country=kr` | `country=kr`; 별도 한국어 텍스트 필터 없음 |
| 정렬 | MOST_RELEVANT | mostrecent |
| 수집 범위 | reviews_all 호출 | 1~10페이지, 오류/자료 없음이면 중단 |
| 별점 수집 필터 | `filter_score_with=None`, 전체 별점 | 별점 제한 없이 수집 |
| 후속 날짜 조건 | 2021-01-01~2024-11-01 | 같은 날짜 범위 |
| 산출물 이름 | reviews_20210101_to_20241101.csv | appstore_reviews_1456559188_filtered.csv |
| 실제 수집량 | 미제공 | ‘96개밖에 없어 조정 필요’라는 작업 메모, 파일 재집계 미확인 |

별점별 분석은 수집 이후 과정이다. ‘1~2점만 크롤링했다’고 쓰지 않는다. 제공 문서상 낮은 별점 1~2점, 높은 별점 4~5점을 나누어 분석했다. 이 분류를 구현한 코드와 리뷰별 라벨은 없다.

## 사용자가 정리한 분석 건수

| 별점 구간 | 범주 | 건수 |
|---|---|---:|
| 1~2점 | 업데이트 문제 | 616 |
| 1~2점 | 알림 문제 | 225 |
| 1~2점 | 기능 부족 | 247 |
| 1~2점 | UI 불편 | 144 |
| 4~5점 | 앱 기능 만족 | 227 |
| 4~5점 | 아티스트 관련 만족 | 146 |
| 4~5점 | 라이브 경험 | 110 |

616+225+247=1,088은 범주 건수 합계다. 범주 중복·리뷰별 분류 기준·스토어별 출처·전체 리뷰 수가 없어 ‘고유 불만 리뷰 1,088개’라고 확정하지 않는다. 기능 부족은 기능 오류와도 다르므로 합계를 모두 버그 건수로 표현하지 않는다. 비중·대표성·현재 앱의 문제 규모는 추정하지 않는다.

## 분석 한계와 코드 검토

- 종료일은 datetime 2024-11-01 00:00:00이므로 11월 1일 하루 전체가 포함된다고 단정하지 않는다.
- App Store는 최신순 RSS 최대 10페이지에서 받은 항목을 날짜로 거른다. 해당 4년의 전체 리뷰를 확보한 것이 아니다. 메모 96개도 필터 전/후가 불명확하다.
- App Store 날짜의 timezone을 제거해 비교한다. 지역 시간 정합성을 검증했다고 쓰지 않는다.
- 관련성순/최신순은 무작위 표본이 아니다. Google Play `reviews_all`도 모든 지역·언어·역사 리뷰를 보장하는 근거로 사용하지 않는다.
- 코드에 저장 필드 userName이 있으나 실제 작성자별 자료는 공유받지 않았다. 추후 CSV를 요약할 때 작성자 이름을 제외한다.
- 문서의 위버스 내부·커뮤니티 피드백은 출처 후보이며 수집 방법·건수는 미확인이다.

## 지원서에 사용할 범위

확인 가능한 행동: Python으로 앱 리뷰 수집 코드를 직접 작성, 국가·날짜·정렬 조건 설정, 낮은/높은 별점별 불편·만족 범주 정리. 원본 결과 파일을 보기 전 정확한 고유 리뷰 수·자동 분류 정확도·중복 제거·분류 알고리즘을 추가하지 않는다. 팬레터·번역이 위 표의 최다 불만이라는 근거도 없으므로 두 기능의 선택 이유를 이 건수만으로 만들지 않는다.
