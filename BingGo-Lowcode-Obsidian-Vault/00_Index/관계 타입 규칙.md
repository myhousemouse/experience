# 관계 타입 규칙

태그: #ontology #relationship-rule

## 목적

Obsidian 그래프에서 단순 링크가 아니라 문서 간 의미를 읽기 쉽게 하기 위한 관계 규칙이다.

## 관계 타입

- `defines`: 문제, 목표, 기능 범위를 정의한다.
- `evolves-to`: 초기 아이디어나 구조가 이후 버전으로 발전한다.
- `implements`: 기획/명세를 실제 구현한다.
- `replaces`: 기술 제약 때문에 기존 접근을 대체한다.
- `supports`: 근거 자료가 기획 판단을 뒷받침한다.
- `documents`: 회의, 명세, 산출물이 과정을 기록한다.
- `conflicts-with`: 초기 계획과 최종 구현이 다를 때 표시한다.
- `source-of-truth`: 충돌 시 우선 기준이 되는 문서다.
- `interview-evidence`: 면접에서 경험 설명 근거로 사용할 수 있다.

## 충돌 기준

이 프로젝트는 로우코드 툴 제약이 커서 초기 정석 아키텍처와 최종 구현 방식이 다를 수 있다. 충돌이 있으면 다음 순서로 판단한다.

1. 최종 개인 정리 페이지와 결과물
2. 협업 페이지의 최신 API/회의 기록
3. 초기 MVP/전체 구조 문서
4. 아이디어 탐색 기록
