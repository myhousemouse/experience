# 면접용 포인트

태그: #interview #storytelling #career

## 한 줄 요약

로우코드 툴 기반 공모전에서 빙판길 안전 문제를 해결하기 위해 시민 제보, 공공데이터, AI 챗봇을 결합한 서비스를 만들었고, 툴 제약 때문에 초기 아키텍처를 현실적으로 조정해 작동 가능한 MVP를 완성한 경험.

## 문제 상황

- 겨울철 결빙 정보는 분산되어 있고 실시간성이 부족했다.
- 로우코드 공모전이었지만 지도, DB, API, AI 연동을 모두 다뤄야 했다.
- 플렉스튜디오는 출시 초기 툴이라 FlexDB/FlexSQL, 커스텀 API, 사진 DB, 좌표 반환 관련 가이드가 부족했다.

## 판단

- 정석적인 Spring+PostgreSQL+RAG 구조만 고집하면 일정 내 MVP 완성이 어려웠다.
- 사용자가 가장 먼저 필요로 하는 것은 지도 완성도보다 `위험 구간을 빠르게 파악하고 제보할 수 있는 흐름`이라고 판단했다.
- 그래서 일부 기능은 Google Sheets와 로우코드 커넥터를 활용하는 방향으로 우회했다.

## 행동

- 네이버 지도 API와 GPS 기반 위치 정보를 로우코드 앱에 붙였다.
- 시민 제보 데이터를 Google Sheets에 저장하고 리스트로 조회되도록 구성했다.
- 위험도순/최신순 조회 흐름을 설계했다.
- OpenAI API 직접 호출과 프롬프트 엔지니어링으로 챗봇 구조를 경량화했다.
- 플렉스튜디오 디스코드 지원 채널을 활용해 팀 내 기술 병목을 풀었다.

## 결과

- 위험도 TOP 10, 시민 제보, AI 챗봇 중심의 MVP를 구성했다.
- 초기 정석 아키텍처와 실제 구현 가능성 사이에서 현실적인 선회를 경험했다.
- 로우코드 환경에서도 API, DB, 위치 데이터, AI 연동을 제품 관점에서 조합하는 경험을 쌓았다.

## 직무별 어필

- PM/기획: 문제정의, 사용자 가치, MVP 범위 조정, 제약 기반 의사결정
- PO/서비스기획: 공공데이터+시민참여 데이터 결합, 기능 우선순위 조정
- AX/AI기획: AI 챗봇 적용 범위 판단, RAG 대신 경량 프롬프트 구조로 선회
- 개발협업: API 명세, 데이터 흐름, Google Sheets 대안 설계, 로우코드 연동
