## 역할 성격

이 프로젝트는 로우코드 공모전이기 때문에 기획/개발 역할이 명확히 분리되지 않았다. 실제 기여는 `로우코드 학습 리더`, `백엔드/API 연동`, `데이터 파이프라인 설계`, `기술 제약 대응`, `기획 고도화`에 걸쳐 있다.

## 초기 역할분담상 담당

- Spring 공용 API 정리 및 문서화
- Swagger/Postman 기준 API 설계
- Python RAG 서버 호출부 구현 방향 정리
- `/api/roads`, `/api/report`, `/api/risk`, `/api/rag/query` 공용 API 설계
- 로그 관리 방향 검토

## 실제 기여로 정리할 내용

### 로우코드 기반 데이터 파이프라인

- 시민 제보 기능을 백엔드 의존 없이 로우코드 내부에서 독립적으로 구동하는 방향을 설계했다.
- 네이버 지도 API를 연동해 실시간 GPS 위도/경도 값을 받고, 역지오코딩으로 실제 주소를 얻는 흐름을 구현했다.
- 사용자 입력값, 위험 등급, 설명, 위치 데이터를 결합해 저장 가능한 데이터 형태로 구성했다.

### Google Sheets 대안 저장소 도입

- FlexDB/FlexSQL 연동 가이드 부족과 커넥터 제약으로 Spring 서버 전송 계획이 난항을 겪었다.
- 공식 문서와 커넥터 지원이 상대적으로 명확한 Google Sheets API를 대안 저장소로 선택했다.
- 시민 제보 데이터를 Google Sheets에 적재하고 앱 내 리스트와 바인딩하는 방향으로 안정화했다.

### 사용자 중심 조회 로직

- 저장된 제보 데이터를 실시간 호출해 앱 화면에 표시했다.
- 최신순, 위험도순 등 사용자가 당장 필요한 정보를 먼저 볼 수 있는 정렬 기준을 구성했다.

### 팀 학습 리딩

- 출시 초기 단계의 플렉스튜디오 사용법과 제약을 직접 탐색했다.
- 공식 디스코드 1:1 기술 지원 채널을 활용해 막힌 부분을 확인했다.
- 학습한 내용을 팀원에게 공유하며 개발 병목을 줄이는 역할을 했다.

### 기획 고도화

- 설문조사 결과를 바탕으로 시민 제보 참여 의사를 서비스 핵심 가치로 연결했다.
- `시민 참여형 안전망`이라는 기획 방향을 기능 구조와 발표 논리로 연결했다.

## 면접에서 말할 때

이 경험은 “로우코드로도 개발이 쉬웠다”가 아니라, “도구의 제약을 이해하고, 일정 안에 서비스를 작동시키기 위해 아키텍처를 조정했다”는 경험으로 설명하는 것이 좋다.
