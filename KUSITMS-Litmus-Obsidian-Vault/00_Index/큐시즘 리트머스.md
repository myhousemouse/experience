## 2026-10-14 최신 확인 — 새 자소서 작성 시 우선 적용

출처: SK브로드밴드 자소서 작성 대화의 사용자 설명·정정. 개인 진술이며 독립 인증 아님. 아래 내용과 기존 본문이 다르면 아래 최신 범위를 적용한다.

- 백오피스 관심과 경영정보학 복수전공을 배경으로 PM·고객사 소통 플랫폼 기획에 참여했다. 기획 담당이며 팀 전체 개발을 단독 수행한 것으로 쓰지 않는다.
- PM 2명과 IT 외주 경험 고객 50명을 조사해 분산된 소통 채널과 IT 용어 이해·질문의 어려움을 파악했다. 조사 방식·응답 비율은 미확인이다.
- 처음부터 고객사 한 곳 이상이 실제 소통에 사용하는 것을 목표로 삼았다. 회의록 보관함은 파편화된 기록 추적, 문장·단어별 질문은 이해하지 못한 부분의 질문 편의를 위해 설계했다. 자동 요약·문장별 질문은 정규 기간에 팀이 구현했고 이후 고객사 사용 단계에서도 사용됐다고 확인했다.
- 약 한 달의 정규 프로젝트·시험기간으로 실제 도입까지 못했으나 팀은 기업 프로젝트 대상을 받았다. 대표에게 추가 개발 한 달을 제안했고 후속 약 4주 AX 교육형 인턴으로 출퇴근했다. 추가 개발과 인턴을 하나의 한 달로 합치지 않는다.
- 팀 플랫폼과 현업 흐름이 맞지 않았다. 기존에는 없던 프로젝트별 단계 설정이 추가 관리 부담이었다. 단계 설정을 빼고 홈에 Figma·개발 서버를 임베드해 결과물을 바로 보는 방안을 제안했다. 사내 대시보드 연동은 점진적 확대 방향이다. 제안과 실제 반영 범위를 구분한다.
- 서로 다른 고객사 두 곳의 시범 사용을 확인했고 본인 계약 종료 후에도 정식 사용 중이라고 설명했다. 본인 계약 종료를 고객사 계약 종료로 해석하지 않는다. 현재 활성 고객 수는 별도 미확인이다.
- PM은 기존 5개 초과 채널을 사용 시 1~2개로 줄일 수 있다고 예상했다. 실제 감소·절감률로 바꾸지 않는다.
- 팀원 8명이라는 최신 설명과 기존 5명 기록이 다르므로 전체 인원은 확인 전 빼고 쓴다. 베타 시점도 이전 6월 초·AX 후반 설명 차이가 있어 정확한 날짜를 확정하지 않는다. 개인 기여율 미확인.

재사용 에피소드: **LT-Q1 실제 사용 목표를 수상 이후 도입까지 이어간 경험**. 상황·최초 목표→양측 조사·MVP→기간 제약→연장 제안·현업 흐름 수정→고객사 두 곳 시범 사용. 수상과 실사용은 다른 결과다.

## 역할

큐시즘 IT경영학회에서 리트머스라는 IT 외주개발사와 진행한 산학협력 기업 프로젝트다. 리트머스가 과제를 제시하고, 팀이 이를 바탕으로 고객사 전용 프로젝트 관리 플랫폼을 기획, 디자인, 개발했다.

초기 1차는 2026.02.08 ~ 2026.03.16에 진행했고, 이후 한 달 연장하여 2026.04.16까지 수행했다. 1차와 2차를 엄격히 나누기보다는, 기업 과제 수행 이후 핵심 기능을 더 고도화한 연장 프로젝트로 본다.

사용자는 기획파트로 참여했다.

## 제품 정의

리트머스 고객사가 외주 개발을 맡긴 뒤 프로젝트 진행 상황, 문서, 미팅, 해야 할 일, 문의/요청을 한 곳에서 확인하고 처리할 수 있게 돕는 B2B 파트너 플랫폼이다.

핵심 문제는 IT 비전공 고객사가 외주 개발 과정에서 현재 단계, 다음 액션, 문서/피드백 흐름을 이해하기 어렵다는 점이다.

## 기획 우선순위

1. 기업 대표님과의 미팅에서 확인된 요구사항
2. 최신 회의록
3. 최종 GUI와 실제 개발된 플랫폼 화면
4. 최종보고서와 최종발표에 정리된 방향성
5. 유저 리서치, PM 인터뷰, MAZE UT 결과
6. 오래된 내부 회의록의 논의/결정사항

기업 과제 프로젝트이므로, 내부 아이디어보다 기업 미팅에서 확인된 요구사항과 최신 회의록, 최종 GUI/개발 화면을 더 우선한다. 최종 GUI는 전체 화면이 개발 완료된 상태다.

Figma 최종 GUI의 기능 우선순위는 빨간불, 초록불, 파란불 순서다. 각 페이지에서 빈값이거나 없는 화면은 미팅 중 필요하지 않다고 결론이 나 작업하지 않은 범위로 본다.

## 면접 포인트

이 프로젝트의 핵심 면접 포인트는 실제 기업 과제에서 문제 정의를 하고, 기업 피드백을 받아 MVP 범위를 조정한 뒤, 개발 완료와 실제 기업 사용까지 이어낸 경험이다. 특히 기획자가 개발 협업 과정에서 로그인/인증/회원가입의 복잡한 진입 로직, 회의기록, 문서함, QA 기능의 필요성과 우선순위를 조율한 점이 중요하다.

기업 과제 이후에는 대표님 제안으로 2026.04.20 ~ 2026.05.15 주 5일 출근하는 [[리트머스 AX 교육형 인턴]]으로 이어졌다. 이 경험은 기획-디자인-개발 분업이 느린 상황에서 문제 정의, UX 개선, 기능 구현까지 빠르게 연결한 실무 경험으로 정리한다.

## 추가 자소서 활동 기록 — LP-02

출처: [[삼성 자소서 원문]] 2번 성장 과정 첫 소제목.

- 문제: 견적 문의·구두 계약·PM 배정·착수 등 고객마다 진입 상태가 달라 일률적 권한 부여가 어려웠다.
- 수행: 기획 팀원과 서면 1회·대면 2회 인터뷰 및 외주 경험자 조사를 진행했다. 대표에게 착수 과정·데이터를 요청해 고객 상태를 구분하고 견적 문의를 최초 진입점으로 정했다. 계약·착수 단계에 따라 권한이 확장되는 구조와 사내 대시보드 연동을 제안했다.
- 결과 기록: 원문은 기업 프로젝트 대상과 인턴 제안을 기록한다. 구체적인 권한 정책의 개인 기여는 요구분석·설계·제안이다.
- 범위·확인 사항: 삼성 팀 인원 8명은 기존 사용자 제공 5명과 다르므로 별도 확인 사항으로 보관한다. 이 단계에서 QA 시트를 설계했다는 기록과 LP-03에서 제외했다는 기록은 기획 단계 변화를 보여준다.

## 추가 자소서 활동 기록 — LP-03

출처: [[CJ 자소서 원문]] 3번 어려움·실패와 끝까지 시도.

- 문제: 순차적인 외주 개발을 전제로 기획했지만 개발이 진행된 후 실제 현업은 프로토타입 컨펌과 기획·디자인·개발이 병행됨을 알았다. 마감까지 일주일이었다.
- 수행: 대표에게 추가 미팅을 요청하고 고객이 현재 결과물과 할 일을 빨리 파악하는 구조로 목표를 바꿨다. 설계·디자인한 QA 기능도 제외하고 문서·피드백·미팅·TODO 흐름을 재구성했다. 채팅형 소통과 문장별 피드백이 가능한 미팅기록을 다시 설계하고 파트별 구현 범위를 조율했다.
- 결과 기록: CJ 초안은 MVP 완성·대상 수상·실사용을 기록한다. 추가 개발을 먼저 제안해 한 달 연장했고 이후 AX 인턴으로 이어졌다.
- 범위·확인 사항: 확정 기간은 2026.02.08~03.16, 연장 종료 04.16이다. 마감 일주일은 원문 사건 설명. 기존 설계 문서의 QA 항목은 초기안일 수 있으므로 파일 자체를 삭제하거나 모든 QA 업무를 없앴다고 단정하지 않는다. 실제 사용 범위·수상 공식명은 별도 근거 확인 대상으로 남긴다.
