## 한 줄 요약

실제 기업 과제에서 문제 정의를 바탕으로 MVP를 도출하고, 개발 협업을 거쳐 실제 기업이 사용하는 파트너 플랫폼까지 연결한 기획 경험이다.

## 프로젝트 맥락

큐시즘 IT경영학회에서 리트머스와 진행한 산학협력 기업 프로젝트다. 리트머스가 제시한 과제를 바탕으로 고객사 전용 프로젝트 관리 플랫폼을 만들었고, 1차 약 5주 진행 이후 팀이 추가 진행을 제안해 약 한 달 더 연장했다.

기업이 제시한 핵심 문제는 외주개발을 맡긴 고객사가 프로젝트 현황과 자신이 남긴 QA·컨펌·피드백의 반영 여부를 바로 알기 어렵다는 점이었다. 기업 내부에서도 고객사와 기획·디자인·개발팀이 여러 채널의 서로 다른 정보를 보고 있어 프로젝트 단계에 대한 공통 기준이 필요했다. 목표는 양쪽이 같은 정보와 피드백 이력을 확인하는 프로젝트 관리 플랫폼을 만드는 것이었다.

기업 과제 이후에는 대표님 제안으로 2026년 4월부터 5월까지 주 5일 출근하는 [[리트머스 AX 교육형 인턴]]으로 이어졌다.

## 직접 기여

### WorkOS 기반 진입 설계

기업 내부 PM 인터뷰와 사용자 조사를 통해 요구사항을 명세화하고, 로그인·인증, 회의기록, 문서함의 와이어프레임과 기능명세서를 담당했다.

회원가입-로그인 로직이 WorkOS 보안 절차를 거쳐야 해서 진입 설계가 복잡했다. 사용자가 한 명인지 여러 명인지, 개인인지 회사인지에 따라 필요한 진입 화면과 보안 단계를 케이스별로 구조화했다. 화면 설계가 사용자 케이스마다 달라지는 부분은 기존 정기회의 외에 주 1회 스크럼을 추가해 개발팀에 설명하고, 화면별 데이터·권한·예외 조건을 함께 확인했다.

로그인/파트너 페이지 개발 링크: https://partners-page-sooty.vercel.app/

### 회의기록 기능

회의기록 기능을 설계했다. 와이어프레임, 요구사항명세서, 기능명세서 등 개발 전달에 필요한 산출물을 작성했고, 고객사와 PM이 같은 회의 정보를 서로 다른 권한과 목적에서 볼 수 있도록 구조화했다.

사용자 조사에서 고객사가 협업 도구로 노션을 가장 많이 사용한다는 결과를 확인하고, 노션 댓글을 참고해 회의록 안에서 담당자를 멘션하고 피드백을 이어가는 기능을 기획했다. 개발팀은 남은 인력과 일정상 구현이 어렵다는 의견을 냈다. 고객사가 여러 채널을 오가지 않고 피드백의 맥락과 담당자를 확인하려면 이 기능이 중요하다는 근거를 설명하고 구현 범위를 다시 조정했다. 그 결과 제한된 일정 안에 멘션·댓글 기능까지 구현했다.

### 문서함 기능

문서함 기능을 설계했다. 외주 프로젝트에서 기획서, IA, 계약서, 견적서, 디자인 레퍼런스, 기능명세서 같은 산출물이 흩어지는 문제를 줄이기 위해 폴더 구조와 문서 확인 흐름을 잡았다.

### QA 기능

QA 기능은 설계와 디자인까지 완료했지만, 기업 미팅을 진행하면서 별도 기능의 필요성이 낮다고 판단되어 최종 개발 범위에서 제외됐다. 대신 고객 피드백의 맥락을 남기는 회의기록 멘션·댓글 기능을 우선 구현했다. 이 경험은 기능을 많이 넣는 것보다 사용자 근거와 개발 여건을 함께 보고 MVP 범위를 조정한 사례로 정리한다.

## 판단 기준

- 대표님 피드백을 가장 우선했다.
- 회의록끼리 충돌하면 최신 회의록을 더 정확한 기준으로 봤다.
- 최종 GUI는 전체 화면 개발 완료 기준으로 판단했다.
- Figma 최종 GUI의 빨간불, 초록불, 파란불 순서를 기능 중요도로 봤다.
- 빈값이거나 없는 화면은 미팅 중 필요하지 않다고 결론이 나 작업하지 않은 범위로 해석했다.

## 면접에서 강조할 포인트

- 실제 기업과의 과제를 통해 문제 정의에서 개발 완료까지 이어간 경험
- 리서치와 기업 피드백을 바탕으로 MVP 범위를 조정한 경험
- 로그인/인증/회원가입처럼 개발 복잡도가 높은 플로우를 시각화해 협업한 경험
- 회의기록, 문서함, QA처럼 기능별 요구사항을 설계하고 개발 전달 문서로 정리한 경험
- 필요 없는 기능을 제외하는 판단까지 포함한 MVP 기획 경험
- 결과물이 실제 기업에서 사용 중이라는 점
- 기업 과제 이후 인턴으로 이어져 내부 대시보드 AX 개선과 기능 추가를 수행한 점
- 기획안을 전달하는 데서 끝내지 않고 추가 스크럼으로 개발 병목과 해석 차이를 줄인 점
- 사용자 중요도와 구현 난이도를 함께 설명해 멘션·댓글 기능의 범위를 합의한 점
