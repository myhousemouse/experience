# 리트머스 기업 프로젝트 자소서 에피소드

연결 경험: [[큐시즘 리트머스]]
기간·역할: 2026.02.08 ~ 2026.03.16, 연장 종료 2026.04.16; 5인 팀 기획
출처: [[자소서 정리 원문]]. 활용 안내: [[자소서 정리]].

같은 경험의 여러 관점을 에피소드로 나눴다. 동일 사건을 독립 프로젝트 성과로 중복 계산하지 않는다. 회사별 지원동기·입사 후 계획은 사용처로만 연결한다.

## 에피소드 상세

### LP-01 · 기업 과제를 수행하며 현업 AI 학습 기회를 넓히다

**이 에피소드가 잘 맞는 질문:** 기업 협업 / 성장 과정 / 배운 것을 확장 / 현업 이해

- 상황·문제: 외주 프로젝트 PM과 고객사가 진행 상태·수정 요청을 공유하는 플랫폼을 기업과 함께 기획했다.
- 내가 한 행동: 실제 기업 요구를 IA·Flow Chart·와이어프레임으로 구체화하고 협업했다. 대표가 알려준 AI 활용 방식에 관심을 갖고 이후 교육형 인턴에 참여했다.
- 결과·배운 점: 산학협력 경험이 AX 인턴 학습 기회로 이어졌다. 인턴에서 만든 대시보드는 별도 경험으로 연결한다.

**재사용할 때 강조할 관점:** 기업 과제에서 얻은 현업 맥락을 시작점으로, 이어지는 AX-03·AX-01로 성장 서사를 구성한다.

**이미 활용한 문항:** 두산 DDI 도전; LG CNS 인턴 경험의 배경

**원문 위치:** [[자소서 정리 원문]] 132–134, 153행. 반복된 후반부 대신 첫 출현 위치를 기준으로 연결.

**표현·근거 메모:** 하나의 경험처럼 프로젝트 기간과 인턴 기간을 합치지 않는다. 이번 원문에는 기업 프로젝트 자체의 상세 난관·해결 결과가 부족하므로 별도의 완성된 갈등 사례로 확대하지 않는다.

### LP-02 · 고객 진입 상태별 계약·착수 권한을 설계하다

**이 에피소드가 잘 맞는 질문:** 예외 설계 / 현업 요구분석 / 권한 정책 / 시스템 기획

- 상황·문제: 견적 문의·구두 계약·PM 배정·착수 등 고객마다 진입 상태가 달라 일률적 권한 부여가 어려웠다.
- 내가 한 행동: 기획 팀원과 서면 1회·대면 2회 인터뷰 및 외주 경험자 조사를 진행했다. 대표에게 착수 과정·데이터를 요청해 고객 상태를 구분하고 견적 문의를 최초 진입점으로 정했다. 계약·착수 단계에 따라 권한이 확장되는 구조와 사내 대시보드 연동을 제안했다.
- 결과·배운 점: 원문은 기업 프로젝트 대상과 인턴 제안을 기록한다. 구체적인 권한 정책의 개인 기여는 요구분석·설계·제안이다.

**재사용할 때 강조할 관점:** 질문의 핵심에 맞춰 위 행동과 판단을 골라 쓴다.

**이미 활용한 문항:** 삼성 자소서 2번 성장 과정 첫 소제목

**원문 위치:** [[삼성 자소서 원문]] 2번 성장 과정 첫 소제목

**표현·근거 메모:** 삼성 팀 인원 8명은 기존 사용자 제공 5명과 다르므로 별도 확인 사항으로 보관한다. 이 단계에서 QA 시트를 설계했다는 기록과 LP-03에서 제외했다는 기록은 기획 단계 변화를 보여준다.

### LP-03 · 마감 일주일 전 현업 흐름에 맞춰 기획을 다시 세우다

**이 에피소드가 잘 맞는 질문:** 실패 수용 / 목표 재설정 / 집요함 / 범위 조율 / 기업 협업

- 상황·문제: 순차적인 외주 개발을 전제로 기획했지만 개발이 진행된 후 실제 현업은 프로토타입 컨펌과 기획·디자인·개발이 병행됨을 알았다. 마감까지 일주일이었다.
- 내가 한 행동: 대표에게 추가 미팅을 요청하고 고객이 현재 결과물과 할 일을 빨리 파악하는 구조로 목표를 바꿨다. 설계·디자인한 QA 기능도 제외하고 문서·피드백·미팅·TODO 흐름을 재구성했다. 채팅형 소통과 문장별 피드백이 가능한 미팅기록을 다시 설계하고 파트별 구현 범위를 조율했다.
- 결과·배운 점: CJ 초안은 MVP 완성·대상 수상·실사용을 기록한다. 추가 개발을 먼저 제안해 한 달 연장했고 이후 AX 인턴으로 이어졌다.

**재사용할 때 강조할 관점:** 질문의 핵심에 맞춰 위 행동과 판단을 골라 쓴다.

**이미 활용한 문항:** CJ 자소서 3번 어려움·실패와 끝까지 시도

**원문 위치:** [[CJ 자소서 원문]] 3번 어려움·실패와 끝까지 시도

**표현·근거 메모:** 확정 기간은 2026.02.08~03.16, 연장 종료 04.16이다. 마감 일주일은 원문 사건 설명. 기존 설계 문서의 QA 항목은 초기안일 수 있으므로 파일 자체를 삭제하거나 모든 QA 업무를 없앴다고 단정하지 않는다. 실제 사용 범위·수상 공식명은 별도 근거 확인 대상으로 남긴다.
