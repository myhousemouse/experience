# 리트머스 AX 교육형 인턴

원본: https://app.notion.com/p/3483eee3a7048038b868d01bea3cdf45
태그: #internship #ax #litmus #b2b #planning #development

## 보안 기준

사용자가 Notion에 직접 정리한 내용은 vault에 보관한다. 다만 회사 내부 데이터, 고객사명, 개인명, 세부 금액, 실제 화면 캡처는 외부 공개 전에 비식별 처리한다.

## 맥락

큐시즘 리트머스 기업 과제 이후, 대표님은 기존의 기획-디자인-개발 분리 방식이 오히려 작업 속도를 늦추는 측면이 있다고 판단했다. 여건이 되는 팀원들에게 인턴을 제안했고, 사용자는 2026년 4월부터 5월까지 주 5일 출근하는 교육형 인턴으로 참여했다.

인턴십은 실제 업무에 투입되며 AX 개선 과제와 추가 과제를 수행하는 형태였다.

## 근무 조건

- 기간: 2026.04.20 ~ 2026.05.15
- 형태: 주 5일 출근
- 성격: 교육형 인턴, 실무 투입형 과제 수행

일별 실습 내용은 [[실습일지 정리]]에 별도 정리했다.

## 역할 범위

회사의 역할 구조가 기획, UX, 개발로 명확히 나뉘어 있지 않아 문제 정의부터 UX 개선, 바로 개발까지 이어지는 방식으로 일했다.

주요 역할:

- Claude, Codex, MCP, skills, agent, plugin 기반 AX 업무 환경 학습 및 실무 적용
- 내부 대시보드 Nexus UX 개선
- PM 부서 기준 필요한 기능 추가
- 신규 기능 문제 정의
- 프로토타입 기반 기능 제안
- 개발 가능한 형태로 기능 구체화
- 법무팀 신설에 따른 법무/개인정보 관련 기능 프로토타입 및 개발 형태 제시
- 파트너스 플랫폼 수정 요청 구조 고도화 및 QA/UX 개선
- 마케팅팀 협업을 통한 플랫폼 소개 및 IT 취업/AI 콘텐츠 촬영 자료 정리

## 과제 유형

### Nexus 내부 대시보드 UX 개선

Nexus는 도입된 지 얼마 되지 않아 사용 흐름과 정보 구조에서 불편한 지점이 많았다. 기존 화면의 메뉴 구조, 대시보드 정보 우선순위, 부서별 사용 맥락을 확인하고 UX 개선 과제를 수행했다.

대표 캡처: ![[nexus-dashboard-company-full.png]]

주차별 흐름:

- 1주차: 사내 업무 방식, 협업 구조, AX 업무 환경 온보딩
- 2주차: PM, 세일즈, 법무, 대표 미팅 참여를 통한 Nexus 페인포인트 수집
- 3주차: 파트너스 플랫폼 기획 고도화
- 4주차: Nexus QA, UX 개선, 파트너스 플랫폼 버그 대응

실사용자 피드백:

- 대표, CTO, 경영지원팀, PM, 세일즈, 법무 등 약 5개 직무에서 개선 의견 수집
- Notion, 카카오톡 등 여러 채널에 흩어져 있던 정보를 Nexus 중심으로 정리하는 방향의 실무 적용성 확인
- 법무 기능의 경우 수작업으로 나누어 확인하던 업무를 한 곳에서 볼 수 있도록 개선

### PM 부서 기능 추가

각 부서에서 필요한 기능이 충분히 갖춰지지 않은 상태였고, 사용자는 PM 부서 기준으로 필요한 기능을 정의하고 추가했다.

정리 가능한 범위:

- PM이 확인해야 하는 프로젝트/고객사/업무 상태 정보
- 내부 대시보드에서 반복 확인해야 하는 지표와 액션
- 부서별 업무 흐름에 맞춘 메뉴 및 정보 구조
- 고객사 킥오프 및 프로젝트 진행 전 확인해야 하는 항목을 체크리스트 구조로 재구성
- 고객 확인 정보, 프로젝트 시작 전 필수 정보, 유의 항목을 구분해 누락 방지 흐름으로 설계
- 미팅 녹음본, 기존 필수 확인 항목, 추가 요청 메일 정리본, 회의 메모 반영 흐름을 자동화 구조로 제안

구체화한 PM 체크리스트 방향:

- 단순 API 호출 기반 체크리스트 생성 기능
- 기존 Notion 양식과 미팅 기록을 기반으로 자동 정리되는 체크리스트 기능
- 고객에게 받아야 할 정보 약 110개, 프로젝트 시작 전 필수 정보 약 10개, 유의 항목 4개를 구조화
- 전체 확인 포인트 약 124개를 체크리스트 흐름으로 재구성

### 구조화 체크리스트 및 미팅 준비 흐름

미팅 준비 문서에서는 고객사와의 프로젝트 진행을 위해 필요한 확인 항목을 `전달용 원문`, `확인 항목 체크리스트`, `수신된 답변`, `누락/재확인 필요` 구조로 정리했다.

핵심 의미:

- 미팅에서 나온 답변과 남은 리스크를 한 화면에서 추적할 수 있게 구조화
- 프로젝트 상세 화면의 자유형 체크리스트를 구조화된 체크리스트 UI로 바꾸는 방향으로 연결
- MCP에서도 구조화 체크리스트를 읽고 쓸 수 있도록 확장하는 방향으로 정리
- PM이 고객사와 개발팀 사이에서 놓치기 쉬운 외부 연동, 일정, 계정, 약관, 브랜드 자료, QA 일정 등을 체계적으로 관리하는 방식 제안

미팅 준비 문서의 주요 관리 항목:

- 외부 API 문서 제공 시점, 테스트 키, 스테이징 환경
- 고객사 측 소통 담당자와 역할 구분
- 납품일과 실제 출시일 기준 구분
- 결제 정책, PG 진행 정보
- 브랜드 자료, 앱 명칭, 약관, 개인정보처리방침
- Apple Developer, Google Play Console 등 스토어 계정 준비 현황
- 고객 검수 라운드와 와이어프레임 최종 컨펌 일정

디벨롭 체크리스트에서 정리한 구현 연결:

- 프로젝트 상세 화면의 기존 자유형 체크리스트 UI를 구조화 체크리스트 UI로 교체
- 커뮤니케이션 체크리스트 카드를 GitHub 연결 카드 위로 이동
- MCP에서 구조화 체크리스트를 읽고 쓸 수 있도록 확장
- 구조화 응답을 `sourceMessage`, `sourceHistory`, `checklistItems`, `receivedAnswers`, `missingItems`로 분리

### 법무/개인정보 기능

법무팀이 새로 개설되면서 법무/개인정보 관련 기능을 제안했다. 프로토타입과 개발된 형태로 기능을 제시했지만, 실제 업무 데이터는 기록하지 않는다.

정리 가능한 범위:

- 법무/개인정보 업무를 내부 대시보드 메뉴로 분리
- 관련 문서와 상태를 확인할 수 있는 구조 제안
- 부서 신설에 맞춰 필요한 기능을 빠르게 정의하고 화면화
- 법무 리스크를 프로젝트 단위로 조기 탐지, 우선순위화, 대응 이력 관리할 수 있는 구조 제안
- NDA, 개인정보 처리위탁, 개인정보 파기 일정, 접근 권한, 증빙 관리를 프로젝트 정보와 연결
- PM 화면과 법무 화면은 분리하되 데이터는 양방향으로 연동되는 구조 제안
- 리스크 등급, 분쟁 로그, NDA 만료 알림, 처리위탁 계약 상태, 개인정보 취급 현황을 MVP 범위로 정리

법무/개인정보 기획 세부 구조:

- 법무 리스크 통합 대시보드
- 계약서 AI 비교 및 특약 추출
- 분쟁/대응 타임라인
- NDA 보호기간 자동 추출 및 만료 알림
- 개인정보 취급 현황, 파기 일정, 접근 가능자 관리
- Teams 알림 및 프로젝트 페이지 연동
- 프로젝트 상세 내 법무/분쟁 기록 탭
- 프로젝트 상세 내 개인정보/NDA 관리 탭
- 알림 및 감사 로그

리스크 등급:

- 정상: 일정, 계약, 대금, 이슈 상태가 정상인 프로젝트
- 관찰: 마일스톤 지연 또는 PM 이슈 조짐 발생
- 주의: 계약 종료일 임박/경과, 대금 이슈, 고객사 클레임 발생
- 경고: 계약 해지 언급, 내용증명 수신/발송 등 법적 분쟁 전조 확인
- 위험: 소송, 중재, 지급 거절 확정 등 실질적 분쟁 단계

MVP 우선순위:

- 1차: 리스크 등급 대시보드, 분쟁 로그, NDA 만료일 등록 및 알림, 처리위탁 계약 상태 관리, 개인정보 취급 현황 및 파기 일정
- 2차: AI 계약서 비교 자동화, 포트폴리오 활용 조항 자동 추출, 알림 고도화, 감사 로그 상세화
- 3차: 리스크 점수화 모델, 유사 분쟁 사례 추천, 개인정보 취급 현황 이상 패턴 감지

### 고객사/영업/리드 관리 흐름

대시보드의 주요 개선 범위는 특정 부서 화면에만 한정되지 않고, 고객사, 영업, 리드 문의, 프로젝트 관리가 하나의 운영 흐름으로 이어지도록 정리하는 방향이었다.

세일즈 관련으로는 계약 정보와 Nexus 데이터 연동, 프로젝트 히스토리 반영, 합계액 불일치, 세일즈-PM 역할 경계가 유동적인 환경을 대시보드 구조에 반영하는 방향을 검토했다.

세일즈 미팅에서 확인한 방향:

- 문의 flow를 파트너스 플랫폼으로 바로 뜨게 연동
- Nexus 상태와 MCP 연결 상태 확인
- 결산안 예정건 포함 연동 방식 검토
- 세일즈 현황과 Google Sheet 기반 결산안 정보를 Nexus와 연결하는 방향 검토

### 파트너스 플랫폼 고도화

기존 큐시즘 리트머스 과제로 수행했던 파트너스 플랫폼을 실제 고객사 사용 단계에 맞춰 고도화했다. 고객이 제작 중인 프로젝트를 보면서 수정 요청을 바로 전달할 수 있도록, 수정 요청 접점을 홈 영역과 관리 탭에 더 명확하게 배치하는 방향이었다.

정리 가능한 범위:

- 고객 수정 요청을 사내 QA/티켓 흐름과 연결
- 고객이 남긴 요청을 확인하고 관리할 수 있는 탭 구조 고도화
- 실제 고객 사용 흐름을 기준으로 파트너스 플랫폼 UX와 운영 구조를 점검
- 고객이 실제 제작 중인 프로젝트를 보며 수정사항을 바로 전달할 수 있는 구조 반영
- 수정 요청 섹션을 홈 히어로 영역에 배치해 사용성을 높이는 방향으로 고도화
- 도입 대상 고객사 8곳, 선사용 고객사 1곳, 일평균 10건 내외 티켓 흐름을 확인한 내용 기록

### 마케팅팀 협업

인턴십 중 마케팅팀과도 협업했다. 업무 범위는 플랫폼 소개와 IT 취업/AI 전환 관련 촬영 자료 정리로 확인된다.

정리 가능한 범위:

## 면접용 포인트

- 기업 과제 이후 실제 인턴으로 이어진 경험
- 기획-디자인-개발이 분리되지 않은 환경에서 문제 정의부터 개발 가능한 기능까지 빠르게 연결한 경험
- 도입 초기 내부 대시보드의 UX 문제를 발견하고 개선한 경험
- PM 부서 관점에서 필요한 기능을 정의한 경험
- 고객사 미팅 준비, 수신 답변, 누락 항목을 구조화해 PM 업무 누락을 줄이는 흐름을 만든 경험
- 법무팀 신설이라는 조직 변화에 맞춰 새로운 기능을 프로토타입과 개발 형태로 제안한 경험
- 법무/개인정보처럼 기존에 제품 안에 없던 업무 도메인을 리스크 등급, 알림, 권한, 감사 로그, 프로젝트 상세 탭으로 분해한 경험
- 파트너스 플랫폼의 실제 고객 사용 흐름을 기준으로 수정 요청 구조를 고도화한 경험
- AX 도구를 단순 학습이 아니라 실무 기능 기획, UI 개선, QA, 자동화 구조에 연결한 경험
- 마케팅팀과 협업하며 제품 기능을 외부 메시지와 콘텐츠로 전환한 경험
- 회사 데이터는 공개하지 않고, 문제 유형과 기여 방식 중심으로 설명할 수 있는 경험

## 이력서용 문장 후보

- 사내 AX 업무 환경에서 Claude, Codex, MCP, skills, agent, plugin 기반 툴체인을 학습하고 실무 적용 경험을 축적함
- PM, 세일즈, 법무, 대표 미팅 18회 이상 참여하며 베타 단계 사내 대시보드 Nexus의 운영상 페인포인트를 수집하고 기능 개선안을 도출함
- 고객사 확인 정보 110개, 프로젝트 시작 전 필수 정보 10개, 유의 항목 4개 등 총 124개 확인 포인트를 반영한 PM 체크리스트 자동화 기능 2종을 기획함
- 기존에 분산돼 있던 협업 흐름을 Nexus 중심으로 재정리하는 과정에서 메모 기반 협업 구조와 법무 전용 탭 기획에 참여함
- 법무팀 신규 기능 기획 과정에서 바이브 코딩 기반 퍼블리싱 초안을 약 1시간 내 제작해 와이어프레임 대체 수준의 논의 자료를 빠르게 제시함
- 대표, CTO, 경영지원팀, PM, 세일즈, 법무 등 약 5개 직무의 실사용자 피드백을 반영해 Nexus의 사용 편의성과 현업 적합도 향상에 기여함
- 파트너스 플랫폼의 고객 수정 요청 접점을 홈 메인 섹션으로 재구성하고, 실제 사용 고객사의 일평균 10건 내외 요청 흐름을 고려한 관리 구조를 고도화함
- 마케팅팀과 협업해 파트너스 플랫폼의 홍보 포인트를 정리하고 관련 자료를 전달하며 서비스 소구점 도출 과정에 참여함
- Nexus QA 및 UX 개선 과정에서 UI 사용성 이슈 약 5건을 수정하고 플랫폼 버그 대응을 수행함

## 면접 답변용 핵심 포인트

- 단순히 기능을 만드는 것보다, PM, 세일즈, 법무처럼 서로 다른 직무가 어떤 정보에서 막히는지 파악하고 그 흐름을 구조화한 경험
- AI 도구를 단순 실습용이 아니라 실제 실무 워크플로우와 연결해보며 AX 환경에서 일하는 방식을 익힌 경험
- 베타 단계 플랫폼에서 요구사항 수집, 기능 기획, 초안 제작, 피드백 반영, QA까지 한 사이클을 경험
- 와이어프레임 대신 빠른 퍼블리싱 초안을 제시해 논의 속도를 높이고, 실사용자 피드백을 반영해 점진적으로 고도화한 경험
- 제품 기획뿐 아니라 마케팅 협업, 홍보 콘텐츠 참여, 사내 문화 경험까지 병행하며 서비스와 조직을 다각도로 이해한 경험
