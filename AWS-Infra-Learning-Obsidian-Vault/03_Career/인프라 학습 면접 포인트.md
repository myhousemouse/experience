# 인프라 학습 면접 포인트

## 한 줄 경험

AWS 직무체험과 코멘토 부트캠프를 통해 EC2, VPC, 보안그룹, 웹서버, RDS, 모니터링, 서버리스 API, 비용 산정까지 실습하며 백엔드/PM 관점의 인프라 이해를 쌓았다.

## 백엔드 직무로 말할 때

- EC2 인스턴스를 생성하고 웹서버를 설치해 외부에서 접근 가능한 테스트 페이지를 배포한 경험
- VPC, 서브넷, 인터넷 게이트웨이, 라우팅 테이블, 보안그룹의 관계를 실습으로 이해
- RDS와 웹서버 연계, 모니터링, 서버리스 API, 성능 테스트의 기본 흐름을 학습
- 백엔드 API가 실제 서비스로 노출되려면 포트, 네트워크, 권한, 운영 비용까지 고려해야 함을 이해

## PM/기획 직무로 말할 때

- 개발 일정과 리스크를 이해하기 위해 인프라 기본 구조를 학습한 경험
- 화면/기능 요구사항뿐 아니라 배포 환경, 운영 비용, 장애 가능성까지 고려하려는 태도
- 개발자와 소통할 때 EC2, 보안그룹, RDS, 모니터링 같은 용어를 맥락 있게 이해할 수 있음

## 면접 답변 예시

> 별도 AWS 직무체험과 코멘토 부트캠프에서 EC2, VPC, 보안그룹, 웹서버, RDS, 모니터링, 비용 산정을 실습했습니다. 이 경험을 통해 백엔드 API는 코드 작성에서 끝나는 것이 아니라, 외부 접근 경로, 포트, 보안그룹, 서버 설정, 비용 구조가 맞아야 실제 서비스가 된다는 점을 이해했습니다. PM 관점에서도 배포와 운영 리스크를 알고 있으면 개발자와 일정이나 장애 대응을 더 현실적으로 논의할 수 있다고 느꼈습니다.

## 주의할 표현

- “AWS를 운영했다”보다는 “AWS 기반 배포/인프라 흐름을 실습했다”가 정확하다.
- “상용 서비스 배포”보다는 “EC2 기반 웹서버 배포 실습, RDS/모니터링/서버리스 API 학습”으로 말한다.
- 비용 산정은 실무 운영 경험이 아니라 AWS Pricing Calculator 기반 학습 경험으로 말한다.
