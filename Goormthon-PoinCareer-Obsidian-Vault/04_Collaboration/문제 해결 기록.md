# 문제 해결 기록

태그: #problem-solving #backend #collaboration

## 1. 태그/추천 구조 확장성

문제: 포인트 활동, 채용 공고, 사용자 관심사를 모두 태그/카테고리와 연결해야 했다.

해결: 공통 Category 구조와 도메인별 조인 테이블을 두어 N:M 관계로 설계했다.

의미: 추천, 필터링, 관심사 저장을 같은 기준으로 처리할 수 있게 되었다.

## 2. JPA 공통 필드 이해

문제: BaseEntity와 `@MappedSuperclass`를 처음 다루며 createdAt, updatedAt 같은 공통 필드 처리 방식이 낯설었다.

해결: 테스트와 스터디를 통해 Entity 상속 구조와 JPA 매핑 방식을 이해했다.

의미: 반복 필드를 공통화하고, 도메인 Entity를 더 일관되게 구성할 수 있었다.

## 3. Figma UI와 기능 명세 불일치

문제: 실제 Figma 화면과 초기 기획/기능 명세가 맞지 않는 부분이 있었다.

해결: UI 담당자와 1:1로 조율하고, Notion 기능 명세서와 GitHub Issue를 함께 업데이트했다.

의미: 개발 기준을 화면, 명세, 이슈 단위로 맞추는 협업 방식을 경험했다.

## 4. Docker/EC2 배포 문제

문제: Docker Compose, 환경 변수, 포트, 권한, GitHub Actions 설정에서 여러 오류가 발생했다.

해결: 로그를 확인하며 환경 설정을 분리하고, 포트 매핑과 권한 설정을 조정했다.

의미: 로컬에서 동작하는 코드를 실제 서버에서 시연 가능한 상태로 올리는 과정을 경험했다.

## 5. 프론트 연동 기준 차이

문제: 인증 토큰 전달 방식과 API 요청 형식에서 프론트엔드와 기준이 달랐다.

해결: Swagger와 API 명세를 기준으로 헤더 전달 방식, CORS, 인증 흐름을 맞췄다.

의미: API 구현 자체보다 API 계약을 정확히 공유하는 것이 중요하다는 점을 배웠다.
