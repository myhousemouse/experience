# QA 업무 진행 가이드

**[ 프로세스 정리 ]** 

멘토 안내 → 서비스 확인 → QA 진행 → 발견사항 등록 → 필요 시 Figma 추가 정리 → Re-QA 및 상태 업데이트

**[ 상세 ]**

## 1. 서비스 안내 및 업무 범위 확인

- 멘토가 주차별 QA 대상 서비스와 주요 기능을 안내합니다.
- 안내 내용을 바탕으로 서비스의 이용 흐름과 중점적으로 확인해야 할 영역을 파악합니다.

## 2. QA 진행

- 서비스를 직접 이용하며 기능, 콘텐츠, UI·UX를 점검합니다.
- 정상적인 이용 흐름뿐 아니라 다양한 사용 상황에서 발생할 수 있는 오류와 불편사항도 함께 확인합니다.

## 3. 발견사항 등록

- QA 간 이슈 또는 개선사항을 발견하면 Notion의  [‣](https://app.notion.com/p/3c8bd3d4ae888004810af68a08bf74c7?pvs=21) 에 등록합니다.
- 담당자, 이슈 내용, 발생 조건, 발견자 등을 작성합니다.
- 다른 사람이 보더라도 문제 상황을 이해할 수 있도록 간단하고 명확하게 기록합니다.

## 4. 화면 캡처 후 Figma 아카이빙

- 화면 설명이 필요한 경우 해당 화면을 캡처해 Figma 작업공간에 정리합니다. 
[https://www.figma.com/design/sKATFjPCsiBrhZ0dtr7Q90/QA-인턴-작업-시트?node-id=0-1&t=SJoHydmyNhx7cg8l-1](https://www.figma.com/design/sKATFjPCsiBrhZ0dtr7Q90/QA-%EC%9D%B8%ED%84%B4-%EC%9E%91%EC%97%85-%EC%8B%9C%ED%8A%B8?node-id=0-1&t=SJoHydmyNhx7cg8l-1)
- 문제 영역을 캡쳐하고 필요한 설명을 추가합니다.
- Notion의 해당 발견사항에 Figma URL을 연결해 바로 확인할 수 있도록 합니다.

## 5. Re-QA 및 상태 업데이트

- 수정된 이슈는 담당자가 개발자와 소통하고, 다시 확인해 정상적으로 반영되었는지 검증합니다.
- 각 이슈는 무조건 반영하거나 적용하지 않으며 이슈의 우선순위와 중요도, 프로젝트 시간 분배에 따라 
담당자가 결정합니다.
- 확인 결과에 따라 Notion의 이슈 상태를 업데이트합니다.
