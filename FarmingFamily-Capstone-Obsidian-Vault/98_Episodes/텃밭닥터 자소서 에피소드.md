## 에피소드 상세

### GD-01 · 진단 결과를 후속 상담과 실제 행동으로 연결

**이 에피소드가 잘 맞는 질문:** 고객 중심 문제해결 / AI 서비스 기획 / 직무 선택 이유 / 지원동기의 경험 근거

- 상황·문제: 병해충 진단 결과만으로는 초보 사용자가 대처 방법을 알기 어려웠다. 원문에서는 병해충 상담 비중 79%, 기존 답변 대기 약 일주일을 문제 배경으로 제시한다.
- 내가 한 행동: 진단 직후 추가 질문을 받을 수 있는 챗봇을 제안하고 진단→상담→관리 흐름을 설계했다. 농진청 자료를 파싱·청킹·임베딩해 전문 DB 기반 RAG와 연결했다.
- 결과·배운 점: 진단 뒤 질문에 응답하는 상담 기능을 구현·시연했다. 상담 대기시간 단축 수치는 측정되지 않았다.

**재사용할 때 강조할 관점:** 기술 기능 자체보다 사용자가 다음 행동을 하지 못하는 간극을 발견한 판단을 중심으로 쓴다. AI 진단 모델을 직접 개발한 것으로 표현하지 않는다.

**이미 활용한 문항:** 포스코 사무DX 2번; 두산 DDI 지원동기; 스타벅스 지원동기

**원문 위치:** [[자소서 정리 원문]] 113–123, 163–165행. 반복된 후반부 대신 첫 출현 위치를 기준으로 연결.

**표현·근거 메모:** 79%와 일주일은 원문에 나온 외부 문제 배경 수치로, 조사 출처·대상 확인 전 프로젝트 성과로 사용하지 않는다.

### GD-02 · 기획의 한계를 2주 학습과 직접 구현으로 넘다

**이 에피소드가 잘 맞는 질문:** 도전·몰입 / 새로운 기술 학습 / 역할을 넘어선 실행 / AI 기술 이해 / 기술 PM 역량

- 상황·문제: LLM 연동만으로는 “수원 날씨에서 체리를 재배해도 될까?” 같은 실시간 질문을 처리하지 못했고, 구현 방법을 몰라 기획을 구체화하기 어려웠다.
- 내가 한 행동: Hugging Face·온라인 강의·멘토링으로 2주간 학습했다. 전문지식은 FAISS 기반 RAG, 실시간 정보는 웹 검색, 일반 재배 상담은 LLM으로 처리하는 ReAct 에이전트를 구현하고 FastAPI 서버를 AWS EC2에 배포했다.
- 결과·배운 점: 질문 유형에 맞는 답변 경로를 갖춘 챗봇을 최종 시연했다.

**재사용할 때 강조할 관점:** 왜 개발에 나섰는지→무엇을 학습했는지→구현 구조→시연 순서로 전개한다. 단순 기술 나열보다 특정 질문을 해결한 과정을 보여준다.

**이미 활용한 문항:** 카카오뱅크 인증기획 지원동기; AI Native 역량; LG CNS 직무경험

**원문 위치:** [[자소서 정리 원문]] 6, 31, 149행. 반복된 후반부 대신 첫 출현 위치를 기준으로 연결.

**표현·근거 메모:** 원문 LG CNS 초안의 Pinecone은 이전 사용자 확정에 따라 FAISS로 정정해 재사용한다. 원문 보존본 자체는 수정하지 않는다.

### GD-03 · 질문 유형과 예외 상황을 나눠 챗봇 품질을 점검

**이 에피소드가 잘 맞는 질문:** 품질 검증 / 예외 처리 / 꼼꼼함 / AI 신뢰성 / 테스트 관점

- 상황·문제: 질문별 답변 품질이 달랐고 전문지식·최신 정보·일반 상담을 하나의 응답 방식으로 처리하기 어려웠다.
- 내가 한 행동: 질문을 세 유형으로 나누고 적절한 도구로 라우팅했다. 팀원과 답변을 공유하며 벤치마킹 서비스와 비교하고 예외 질문을 점검했다.
- 결과·배운 점: 유형별 답변과 예외 상황을 확인하는 검증 과정 및 시연 경험을 확보했다. 정확도·유사도 개선율은 제시되지 않았다.

**재사용할 때 강조할 관점:** 대표 입력 질문과 기대 답변 경로를 붙여 설명하면 검증 역량이 분명해진다. 인증기획에는 정상·실패·복구를 확인하는 태도로 연결할 수 있다.

**이미 활용한 문항:** 카카오뱅크 인증기획; AI Native 기획; 포스코; LG CNS

**원문 위치:** [[자소서 정리 원문]] 6, 31, 115, 149행. 반복된 후반부 대신 첫 출현 위치를 기준으로 연결.

**표현·근거 메모:** 정량 유사도 점수·평가 데이터셋을 만들었다고 확대하지 않는다. GD-02와 같은 챗봇 사건의 다른 관점이므로 두 문항에서 반복 사용에 주의한다.
