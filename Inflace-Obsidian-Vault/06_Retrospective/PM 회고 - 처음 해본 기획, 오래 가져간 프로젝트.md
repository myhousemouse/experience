# PM 회고 - 처음 해본 기획, 오래 가져간 프로젝트

원본: https://app.notion.com/p/3853eee3a704819a8393daaf9fa674e3
태그: #retrospective #pm #career

## 역할

인플레이스 프로젝트를 PM 관점에서 회고한 문서다. 취업 준비에서 문제 정의, MVP 판단, 협업 운영, 파트 간 커뮤니케이션, 사용자 검증 경험으로 재구성할 수 있다.

## 핵심 경험

- 처음 PM을 맡으며 문제 정의, 기능 결정, 팀 이해 맞추기, 일정 안에서 선택하는 일을 경험했다.
- 좋은 기능을 많이 넣기보다, 검증하고 싶은 핵심이 무엇인지 판단하는 것이 중요했다.
- 데이터셋 확보와 정제 한계로 주요 기능 일부를 후순위화했다.
- 비대면 협업에서는 회의 전 결정 안건, 회의 후 결정 사항과 액션 정리가 중요했다.
- 개발자 언어와 디자이너 언어를 서로 이해할 수 있게 연결하는 역할을 했다.
- UT를 통해 사용자가 정보량과 도메인 용어에 부담을 느끼는 지점을 확인했다.
- 인스타그램 운영을 통해 서비스가 사용자에게 닿는 과정까지 고민했다.
- 데모데이 이후 베타 운영 단계에서 GA4와 Meta 광고 데이터를 확인하며 랜딩-기능 진입-회원가입 전환 흐름을 분석했다.
- 랜딩 참여 시간은 짧지만 기능 페이지 진입자는 깊게 탐색한다는 점을 근거로, 인플루언서 검색과 경쟁 채널 디폴트 뷰를 로그인 없이 일부 공개하는 개선을 진행했다.
- 랜딩 활성 사용자 183명 수준에서 핵심 기능 진입 사용자 약 30~35명, 회원가입 전환 약 7명을 확인하며 초기 베타 단계의 전환 개선 경험을 쌓았다.

## 취준용 에피소드 후보

- MVP 판단: 데이터셋 한계로 기능을 줄이고 프로젝트 중심을 남긴 경험
- 협업 운영: 비대면 환경에서 회의, Jira, 결정사항, 액션 관리를 한 경험
- 커뮤니케이션: 개발자와 디자이너 사이의 용어와 구현 맥락을 맞춘 경험
- 사용자 검증: UT 결과를 보고 용어/지표 설명, 검색/필터, 빈 상태 문제를 발견한 경험
- 마케팅 확장: 프로젝트 후반 인스타그램 운영으로 사용자 접점까지 확장한 경험
- 데이터 기반 개선: GA4에서 활성 사용자 187명, 조회수 3,898, 이벤트 4,807을 확인하고 전환 이벤트 미설정, 랜딩 CTA 약점, 로그인 장벽 문제를 도출한 경험
- 전환 개선: 핵심 기능을 로그인 없이 일부 공개해 기능 진입 사용자를 약 30~35명으로 늘리고 회원가입 약 7명을 확인한 경험

## 데모데이 이후 운영 에피소드

데모데이 이후 인플레이스를 베타 버전으로 계속 운영하면서 Meta 광고를 집행하고 GA4 데이터를 확인했다. 유입은 있었지만 주요 이벤트가 0으로 잡혀 있어 회원가입, 검색 실행, 채널 분석 실행 등 핵심 행동이 전환 이벤트로 측정되지 않는 문제가 보였다. 또한 랜딩은 183명이 봤지만 평균 참여 시간이 19초로 짧았고, 반대로 `/influencer`, `/videos`, `/channel` 등 기능 페이지에 들어온 사용자는 평균 1분 이상 머물렀다.

이 데이터를 바탕으로 문제를 `제품 가치가 기능 화면 안에서 느껴지는데, 회원가입 장벽 때문에 기능 진입 전에 이탈한다`로 정의했다. 그래서 인플루언서 검색과 경쟁 채널 디폴트 뷰를 로그인 없이 노출해 사용자가 회원가입 전에도 핵심 가치를 확인할 수 있게 개선했다. 이후 랜딩 활성 사용자 183명 수준에서 핵심 기능 진입 사용자는 약 30~35명, 회원가입 전환은 약 7명으로 확인했다.
