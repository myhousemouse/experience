## 2026-10-14 최신 확인 — 새 자소서 작성 시 우선 적용

출처: SK브로드밴드 자소서 작성 대화의 사용자 설명·정정. 개인 진술이며 독립 인증 아님. 아래 내용과 기존 본문이 다르면 아래 최신 범위를 적용한다.

- PM으로 반복 탐색 고객의 편의와 API 비용을 비교했다. 건별 과금의 부담·무제한 구독의 원가 위험을 검토해 저장 데이터 기반 기능은 구독, 호출 비용 발생 기능은 크레딧이라는 혼합 모델을 설계했다.
- 사용자 1,000명·월 서버비 100,000원·VAT 포함 정상가 29,900원·결제 수수료 3.3%·월 AI 비용 여유분 80원 가정. VAT 제외 27,181.82원, 수수료 986.70원, 해당 비용 차감 후 26,115.12원. 서버비 충당 3.829명→정수 4명, 같은 모집단 가정 전환 0.4%다.
- 인건비·마케팅비·관리비와 무료 사용자의 AI 호출 등 원가 범위는 미확정. 사업 전체 손익분기점·실제 수익 실현이라고 쓰지 않는다. 월 80원의 호출 횟수·사용자당 사용량 산정도 미확정이다.
- GPT-4o 호출 7.5~20원, 환율 1,500원, 입력 1,000~4,000·출력 250토큰은 사용자 추정. GPT-5 가격 소개 링크는 GPT-4o 요율 근거로 쓰지 않는다. 토큰 증가와 서버비 증가 조건을 비교했고 실제 비용은 계속 확인해야 한다고 판단했다.
- 얼리버드 서버비별 유료 사용자 12/35/59/117명 표는 얼리버드 가격·비용 조건 미제공이라 재계산 확정하지 않는다. ROI와 서버비 충당 기준을 구분한다.
- 기존 GA4 16→32명 기능 진입은 기간·페이지·사용자 정의 동일 여부 미확인, 가입 7명/20명은 범위 충돌이다. 수익·전환율 개선으로 임의 통합하지 않는다.

재사용 에피소드: **IF-Q5 사용자 편의와 원가를 비교해 과금 정책을 구체화한 경험**. 대안 비교→비용 가정→정상가·서버비/토큰 변화 검토→추정과 실제 수익 구분→운영 가능한 정책. 계산 수치는 시뮬레이션이다.

## 분류 기준

- 캘린더/회의록은 Notion DB의 `페이지 타입`으로 회의록, 이벤트, etc를 구분한다.
- 캘린더/회의록은 `파트` 태그로 BE, FE, PD, PM, ALL, TF-ALL, TF-인스타운영팀, TF-광고팀을 구분한다.
- 파트별 페이지는 PM, PD, FE, BE, marketing 기준으로 작업 맥락을 나눈다.
- Figma GUI 완성본은 기능별 내부 섹션 기준으로 최종 화면을 확인한다.
- 기능 기준이 충돌하면 PRD보다 최종 GUI에 있는 개발 완료 화면을 우선한다.
- PRD는 마지막 `v` 숫자가 붙은 항목을 최종본으로 보고, `EP2`, `EP3`, `EP4`, `EP8`을 우선 범위로 둔다.
- 디자인 시스템은 컴포넌트 섹션 기준, 디자인 파운데이션은 참고 기준으로 둔다.

## 데모데이 이후 베타 운영

데모데이 이후에도 인플레이스를 베타 버전으로 운영하며 실제 사용자 유입과 기능 진입 흐름을 확인했다. Meta 광고를 통해 유입을 만들고, GA4 홈·보고서 개요·웹/앱 트래픽·페이지 및 화면 데이터를 조회해 랜딩에서 핵심 기능으로 이어지는 전환 흐름을 분석했다.

지난 28일 기준 활성 사용자 187명, 새 사용자 176명, 조회수 3,898, 이벤트 4,807이 확인되었지만 주요 이벤트가 0으로 잡혀 있어 회원가입, 검색 실행, 채널 분석 실행, 문의하기 클릭 등 핵심 행동을 전환 이벤트로 설정할 필요가 있었다.

랜딩(`/`)은 활성 사용자 183명, 평균 참여 시간 19초로 짧았고, 반대로 `/influencer`, `/videos`, `/channel` 등 기능 페이지에 들어온 사용자는 1분 이상 머무르는 패턴을 보였다. 이에 따라 인플루언서 검색과 경쟁 채널 디폴트 뷰를 로그인 없이 일부 공개하여 사용자가 회원가입 전 제품 가치를 확인할 수 있도록 개선했다.

개선 이후 랜딩 활성 사용자 183명 수준에서 핵심 기능 진입 사용자는 약 30~35명, 회원가입 전환 인원은 약 7명으로 확인되었다.

## 추가 자소서 활동 기록 — IF-05

출처: [[CJ 자소서 원문]] 2번 직무역량 첫 경험.

- 문제: 반복 탐색하는 사용자의 편의와 호출마다 발생하는 AI 비용을 단일 과금 방식으로 함께 관리하기 어려웠다.
- 수행: 구독과 차감형 크레딧의 혼합 모델을 설계하고 서버비·AI 호출비·결제 수수료를 반영해 손익분기점을 계산했다. 가격과 무료 이용 범위도 구체화했다.
- 결과 기록: 비용을 고려한 정책과 가격·무료 범위를 설계했다. 수익 실현·원가 절감 결과는 제시되지 않았다.
- 범위·확인 사항: IF-03과 같은 과금 정책의 비용 산정 관점. 기존 글로비스 초안은 경쟁 채널 분석을 크레딧으로, CJ 초안은 검색·채널 분석을 구독/AI 분석을 크레딧으로 표현한다. 기능 명칭·버전 차이 확인 전 저장 데이터/AI 호출 기반 기능이라는 비용 기준으로 정리한다.
