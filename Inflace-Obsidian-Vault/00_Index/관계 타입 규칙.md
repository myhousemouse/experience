# 관계 타입 규칙

태그: #ontology #relationship #index

## 목적

인플레이스 Vault에서 문서 링크가 단순한 참조가 아니라, 어떤 의미로 연결되는지 일관되게 표현하기 위한 규칙이다.

## 관계 타입

- 근거: 시장 조사, PRD, 문제 정의, 유저/UT 관찰에서 나온 원천 자료
- 검증: UT, QA, 실제 사용자 반응으로 확인한 내용
- 인사이트: 근거와 검증을 해석해서 얻은 문제, 니즈, 시사점
- 결정: MVP 범위, 기능 우선순위, 발표 방향성, 운영 기준
- 반영: 결정이나 인사이트가 옮겨간 PRD, 기능명세, 화면, API, 마케팅 콘텐츠
- 기준: 충돌이 있을 때 우선해서 따라야 하는 문서나 원본
- 구현: API, FE/BE 개발 룰, Swagger, 개발 협업과의 연결
- 운영: 회의, Jira, QA시트, 협업 규칙과의 연결
- 마케팅: 인스타그램 카드뉴스, 콘텐츠 기획, 브랜드 메시지 확산과의 연결
- 회고: 취준/면접에서 경험으로 재구성할 수 있는 배움
- 후속작업: 아직 남은 개선, 확인, 보완 대상

## 우선순위

1. [[GUI 완성본]]에 있는 실제 개발 완료 화면
2. 실제 구현 화면과 최종 데모 흐름
3. 데모데이 발표 자료에 정리된 최종 방향성
4. PRD 중 마지막 `v` 숫자가 붙은 최종본
5. 기능명세서
6. UT 기록과 QA 기록

기능명세서는 PRD로 흡수된 상태이므로, 기능 기준은 PRD와 최종 데모 흐름을 더 우선한다. 다만 PRD와 최종 GUI가 충돌하면, 실제 개발된 화면이 들어 있는 [[GUI 완성본]]을 최우선 기준으로 둔다.

PRD에서는 `EP2`, `EP3`, `EP4`, `EP8`을 우선 범위로 본다. 나머지 EP는 후순위 또는 확장 범위로 분류한다.

## 핵심 흐름

```text
PRD
-> UT 기록 / QA시트
-> PRD 최종본(v 마지막 숫자)
-> EP2 / EP3 / EP4 / EP8 우선 범위 결정
-> GUI 완성본의 개발 완료 화면
-> FE BE 개발 룰 / API 기본 명세서
-> 데모데이 발표 자료 / 발표 PPT
-> PM 회고 / 인스타그램 운영
```
