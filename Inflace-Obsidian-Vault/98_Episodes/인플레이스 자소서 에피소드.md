# 인플레이스 자소서 에피소드

연결 경험: [[인플레이스]]
기간·역할: JECT 2026.01.31 ~ 2026.07.04; 10인 팀 PM
출처: [[자소서 정리 원문]]. 활용 안내: [[자소서 정리]].

같은 경험의 여러 관점을 에피소드로 나눴다. 동일 사건을 독립 프로젝트 성과로 중복 계산하지 않는다. 회사별 지원동기·입사 후 계획은 사용처로만 연결한다.

## 에피소드 상세

### IF-01 · 활동 지표보다 실제 전환을 성과 기준으로 삼다

**이 에피소드가 잘 맞는 질문:** 원칙·직업윤리 / 성과를 정직하게 보고 / 데이터 기반 판단 / 실패 인정과 개선

- 상황·문제: 활성 사용자 187명·조회 3,898회·이벤트 4,807회에 비해 회원가입이 10명 미만이었다.
- 내가 한 행동: 좋아 보이는 활동 지표만 내세우지 않고 목표 미달을 인정했다. 가입을 핵심 판단 기준으로 마일스톤을 조정하고 모바일 랜딩·기능 공개·히어로 섹션을 개선했다.
- 결과·배운 점: 원문은 개선 후 회원가입자 20명으로 기록한다. 기존 볼트의 다른 측정 기록에서는 가입 전환 약 7명을 기록한다.

**재사용할 때 강조할 관점:** 불리한 수치를 어떻게 받아들이고 성과 기준을 정했는지를 중심으로 쓴다. 개선 결과가 없어도 판단과 행동을 설명할 수 있다.

**이미 활용한 문항:** 농협 직업윤리·원칙

**원문 위치:** [[자소서 정리 원문]] 41–45행. 반복된 후반부 대신 첫 출현 위치를 기준으로 연결.

**표현·근거 메모:** 20명과 기존 약 7명은 기간·누적/신규·분모가 미확인. 임의 통합하지 않는다. 활동량을 전환율로 바꾸거나 가입 “2배”를 확정하지 않는다.

### IF-02 · 로그인 전에 제품 가치를 보여 기능 진입을 개선

**이 에피소드가 잘 맞는 질문:** 데이터 기반 UX / 전환 개선 / 사용자 행동 분석 / 그로스·운영

- 상황·문제: 랜딩 방문자 183명의 평균 참여는 19초지만 기능 페이지 진입자는 1분 이상 머물렀다. 진입 전 장벽을 개선할 필요가 있었다.
- 내가 한 행동: 인플루언서 검색·경쟁 채널 기능 일부를 로그인 없이 공개하고 실제 이용 시점에 로그인하도록 흐름을 바꿨다.
- 결과·배운 점: 첨부 원문은 핵심 기능 진입 16→32명, 기존 기록은 16→약 30~35명으로 약 두 배 방향이 일치한다.

**재사용할 때 강조할 관점:** 유입→랜딩→핵심 기능 진입을 구분해 보여준다. 기능 진입자가 늘어난 결과를 가입 성과와 분리한다.

**이미 활용한 문항:** 스타벅스 직무역량; 농협 윤리 문항의 개선 행동

**원문 위치:** [[자소서 정리 원문]] 167–171, 45행. 반복된 후반부 대신 첫 출현 위치를 기준으로 연결.

**표현·근거 메모:** 기존 16명은 /influencer 활성 사용자, 이후는 핵심 기능 진입 사용자다. 같은 기간·페이지·집계 정의인지 확인 전 엄밀한 개선율로 단정하지 않는다. 로그만으로 로그인 화면 이탈 원인을 확정하기보다 가설과 개선으로 표현한다.

### IF-03 · 사용 패턴과 API 원가를 반영해 과금 구조를 나누다

**이 에피소드가 잘 맞는 질문:** 리스크 예측 / BM·운영 정책 / 비용과 고객 가치의 균형 / 서비스 기획

- 상황·문제: 반복 비교하는 마케터에게 건별 과금은 부담이고, 호출 비용이 발생하는 기능을 무제한 구독으로 제공하면 운영비가 커질 수 있었다.
- 내가 한 행동: 저장 데이터 기반 인플루언서 분석은 구독, API 호출 기반 경쟁 채널 분석은 크레딧으로 구분했다. 구독 포함 크레딧과 구매 크레딧 유효기간·이벤트 활용도 설계했다.
- 결과·배운 점: 기능별 사용·비용 구조를 구분한 정책을 설계했다. 원문은 실제 정책 반영을 기록하지만 매출·원가 절감 수치는 없다.

**재사용할 때 강조할 관점:** 사용자 사용 빈도와 서비스 비용이라는 두 기준을 어떻게 균형 잡았는지 설명한다.

**이미 활용한 문항:** 현대글로비스 발생가능 문제 예측

**원문 위치:** [[자소서 정리 원문]] 80–85행. 반복된 후반부 대신 첫 출현 위치를 기준으로 연결.

**표현·근거 메모:** 유료화·수익 실현·원가 절감이 검증됐다고 확대하지 않는다.

### IF-04 · 예상 문의를 유형·긴급도로 나눠 CS를 설계

**이 에피소드가 잘 맞는 질문:** 선제적 운영 설계 / 예외·고객 대응 / VOC 분류 / 운영 리스크 관리

- 상황·문제: 유료화 이후 데이터 오류·환불·계정 문제·기능 의견이 섞이면 긴급 대응과 개선 의견 수집이 모두 어려울 수 있었다.
- 내가 한 행동: 문의 유형·긴급도를 분류했다. 즉시 해결이 필요한 데이터·계정 문제는 실시간 CS, 개선 의견은 익명 플로팅 버튼 접수 후 관리자 페이지에서 유입경로와 확인하도록 설계했다.
- 결과·배운 점: 예상 문의에 대응하는 채널·접수 흐름을 사전에 구체화했다. 운영 후 처리시간·만족도는 기록되지 않았다.

**재사용할 때 강조할 관점:** 예상 문제→분류 기준→채널 선택→담당자의 확인 흐름 순서로 전개한다. IF-03과 묶으면 사용자·비용·운영을 함께 고려하는 정책 기획 사례가 된다.

**이미 활용한 문항:** 현대글로비스 발생가능 문제 예측

**원문 위치:** [[자소서 정리 원문]] 87–89행. 반복된 후반부 대신 첫 출현 위치를 기준으로 연결.

**표현·근거 메모:** 직접 CS를 장기간 운영하거나 문의를 줄였다는 결과로 바꾸지 않는다.

### IF-05 · 혼합 과금 정책을 비용·손익분기점 검토로 구체화

**이 에피소드가 잘 맞는 질문:** 사업·기술 비용 이해 / 가격 정책 / 손익분기점 / 실행 가능한 IT 과제

- 상황·문제: 반복 탐색하는 사용자의 편의와 호출마다 발생하는 AI 비용을 단일 과금 방식으로 함께 관리하기 어려웠다.
- 내가 한 행동: 구독과 차감형 크레딧의 혼합 모델을 설계하고 서버비·AI 호출비·결제 수수료를 반영해 손익분기점을 계산했다. 가격과 무료 이용 범위도 구체화했다.
- 결과·배운 점: 비용을 고려한 정책과 가격·무료 범위를 설계했다. 수익 실현·원가 절감 결과는 제시되지 않았다.

**재사용할 때 강조할 관점:** 질문의 핵심에 맞춰 위 행동과 판단을 골라 쓴다.

**이미 활용한 문항:** CJ 자소서 2번 직무역량 첫 경험

**원문 위치:** [[CJ 자소서 원문]] 2번 직무역량 첫 경험

**표현·근거 메모:** IF-03과 같은 과금 정책의 비용 산정 관점. 기존 글로비스 초안은 경쟁 채널 분석을 크레딧으로, CJ 초안은 검색·채널 분석을 구독/AI 분석을 크레딧으로 표현한다. 기능 명칭·버전 차이 확인 전 저장 데이터/AI 호출 기반 기능이라는 비용 기준으로 정리한다.

## 삼성·CJ 추가 활용 기록

CJ 2번은 IF-03 과금 모델을 재사용하고 손익분기점·가격·무료 범위 검토를 IF-05로 보강한다. 비용 산정표·금액은 원문에 없어 계산의 수치 결과를 만들지 않는다.
