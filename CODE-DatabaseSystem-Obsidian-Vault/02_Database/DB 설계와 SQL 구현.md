## 설계 범위

최종보고서에는 데이터베이스 설계, 물리적 설계, DML, SQL 조회 예시가 포함되어 있다. 사용 DBMS는 SQLite였고, 남은지는 기본 CRUD SQL을 전반적으로 작성했다.

PDF가 이미지 기반이라 전체 SQL을 텍스트로 추출하지는 못했지만, 주요 페이지에서 테이블과 조회 흐름을 확인했다.

## SQL/물리 설계 방향

보고서에는 `project` 테이블을 조회하는 SQL 예시와 프로젝트 코드, 시작일, 종료일을 조회하는 흐름이 확인된다. 전체적으로 업무 객체를 테이블로 나누고, 프로젝트 코드와 업체 코드 등을 외래키로 연결하는 구조로 보인다.

팀은 테이블을 수기로 그리며 관계 차수와 제약조건을 검토했다. 주문, 자재, 공급, 자재업체, 프로젝트, 건축주, 설계회사, 설계도, 하청업체, 하청내역 등 업무 객체를 놓고 1:N, N:M 관계와 필수/선택 관계를 확인했다.

최종 결과물은 실제 DB 스키마와 데이터 열 구성을 고려한 와이어프레임이었다. 따라서 이 프로젝트의 구현 범위는 "운영 서비스 개발"보다는 "실제 업무 요구 기반 DB 스키마와 CRUD 흐름 설계"로 정리하는 것이 정확하다.

## 이 프로젝트에서 말할 수 있는 개발 포인트

- 요구사항을 엔티티와 속성으로 분해했다.
- 업무 흐름을 ERD와 물리 테이블 구조로 옮겼다.
- SQLite 기반 CRUD SQL을 통해 프로젝트, 자재, 주문, 협력업체 데이터를 다루는 흐름을 설계했다.
- 응용 화면에서 필요한 데이터가 DB 구조와 연결되도록 설계했다.

## 보완 필요
