## 한 줄 요약

실제 건설 회사의 협력업체, 자재, 주문, 프로젝트 데이터를 관리하기 위해 데이터베이스 구조와 응용 시스템 흐름을 설계한 데이터베이스 시스템 수업 프로젝트.

## 프로젝트 맥락

- 제안 기업명: CODE, Carry Out Data Efficiency
- 고객사: TS 종합건설
- 프로젝트 기간: 2023.09.01 ~ 2023.12.15
- 성격: 수업 프로젝트이지만 실제 회사와 협업하며 요구사항을 파악한 프로젝트
- 핵심 산출물: 최종보고서, 발표 PPT, ERD/논리/물리 설계, SQLite CRUD SQL, 데이터 구조 기반 와이어프레임

## 핵심 문제

TS 종합건설은 설립 초기 단계의 건설 회사로, 자재 견적서와 설계 도면 등 주요 자료를 수기 또는 종이 기반으로 관리하고 있었다. 프로젝트마다 협력업체, 자재업체, 주문, 공사 진행 상태가 연결되지만 이를 통합적으로 조회하고 관리할 시스템이 부족했다.

이 문제는 [[01_Planning/실제 기업 협업과 문제 정의]]에서 정리한다.

## 제안 방향

- 프로젝트, 협력업체, 자재, 주문 데이터를 통합 관리
- 컴퓨터 활용 능력이 높지 않은 사용자도 사용할 수 있는 쉬운 UI 설계
- 자재 주문과 협력업체 정보를 빠르게 조회할 수 있는 구조 설계
- 성장 초기 회사가 이후 확장할 수 있는 기초 DBMS 구조 제안

상세 설계는 [[02_Database/협력업체 관리 시스템]], [[02_Database/DB 설계와 SQL 구현]] 참고.

## 내 역할

보고서 기준으로 남은지는 총무 팀장을 맡았고, 킥오프 미팅 전 고객사 산업/업무 특성을 사전 조사했다. 보고서 방향에 대한 의견을 제시하고, 팀원별 강점을 고려해 역할 분배를 제안했으며, 협업 분위기를 조성하는 역할을 수행했다.

개발/DB 측면에서는 SQLite를 사용했고, 기본 CRUD SQL을 전반적으로 작성했다. 팀 전체가 수기로 테이블 관계와 제약조건을 검토한 뒤, 이를 실제 DB 스키마와 데이터 열 구성을 고려한 와이어프레임으로 연결했다.

자세한 내용은 [[01_Planning/개인 기여 정리]] 참고.

## 면접에서 잡을 수 있는 포인트

- 실제 회사 대표님과 2-3회 대면미팅을 진행하며 요구사항을 DB 모델로 옮긴 경험
- 종이/수기 기반 업무를 구조화된 데이터 관리 시스템으로 전환하려 한 경험
- ERD, SQLite, CRUD SQL, 물리 설계를 하나의 업무 문제와 연결한 경험
- 요구사항 분석과 UI 흐름 설계가 DB 설계 품질에 영향을 준다는 점을 배운 경험
