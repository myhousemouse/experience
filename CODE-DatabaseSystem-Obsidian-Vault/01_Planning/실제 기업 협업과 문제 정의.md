## 프로젝트 배경

이 프로젝트는 데이터베이스 시스템 수업에서 진행했지만, 실제 고객사인 TS 종합건설의 업무 상황을 기반으로 문제를 정의했다. 팀은 CODE라는 제안 기업을 설정하고, 고객사의 현 업무 방식에 맞는 데이터베이스 시스템을 제안했다.

실제 회사 대표님과 2-3회 대면미팅을 진행했고, 회사 자료를 제공받았으며 서면 의견도 받았다. 따라서 단순 가상 시나리오가 아니라 실제 현업의 데이터 관리 방식과 요구를 확인하며 진행한 프로젝트로 볼 수 있다.

## 고객사의 현재 상황

- TS 종합건설은 설립 초기의 건설 회사로, 체계적인 DBMS가 없었다.
- 자재 견적서, 설계 도면 등 주요 자료가 수기 또는 종이 형태로 관리되고 있었다.
- 프로젝트별로 협력업체, 자재업체, 주문, 공사 진행 상태가 얽혀 있었지만 통합 조회가 어려웠다.
- 건설 프로젝트 특성상 다수의 협력업체와 빠르게 커뮤니케이션해야 하는 상황이었다.

## 핵심 문제

수기로 관리되는 자재, 업체, 주문, 프로젝트 데이터를 구조화하지 않으면 업무 속도와 정확성이 떨어진다. 특히 건설업에서는 프로젝트마다 협력업체와 자재업체가 반복적으로 연결되기 때문에, 데이터를 체계적으로 관리하지 않으면 주문 누락, 정보 탐색 지연, 커뮤니케이션 비용이 커질 수 있다.

## 요구사항으로 정리한 방향

- 쉬운 UI
- 협력업체, 자재업체, 자재, 주문, 프로젝트 데이터를 한 곳에서 조회
- 자재 주문 프로세스를 데이터 기반으로 관리
- 성장 초기 기업이 이후 기능을 확장할 수 있는 기초 DB 구조 마련

## 이 경험의 의미

이 프로젝트는 단순히 테이블을 만드는 과제가 아니라, 실제 회사의 업무 흐름을 이해하고 이를 데이터 구조로 변환하는 경험이었다. 특히 DB 설계가 현장 업무 이해, UI 설계, 협업 방식과 분리되어 있지 않다는 점을 배운 사례로 정리할 수 있다.

교수님 피드백도 이 방향과 맞닿아 있다. 실제로 고객사는 데이터베이스를 사용하지 않고 수기로 업무를 처리하고 있었기 때문에, 내부에 필요한 데이터베이스 설계를 이해하는 것이 중요했고 그 점이 프로젝트에 잘 녹아들었다는 취지의 피드백을 받았다.
